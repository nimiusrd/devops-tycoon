### RI-101 敗北直前の実質的な選択肢を反実仮想評価できない

RI-89で危険域における介入の機械的な発動可否は記録できるが、その介入が敗北を遅延・回避するかは評価できない。効果の無い介入も「打てる手」に含まれるため、F-8とF-9の有効手を検証できていない。

受入条件:

- 代表的な危険状態を決定論的に複製し、無介入と適用可能な介入・選択肢を同じ乱数状態から分岐比較する。
- 敗北までのスプリント数、危険域からの離脱、最終敗因を記録し、有効な選択肢が残る最後の時点を敗因別に集計する。
- F-8の回復余地とF-9の敗因別の有効手を別々に判定する。
- 状態複製、乱数再現、分岐数の上限、集計規則をユニットテストで固定する。

RI-89の観測結果を入力に使う。難易度は**高**。

### RI-102 スプリント間の戦略層がプレイヤーを急かさないことを検証できない

SPEC F-3のプレイテスト観測項目は追加済みだが、戦略フェーズが入力を待ち続ける自動テスト契約が無い。

受入条件:

- `setup` / `result` / `draft` / `evolution` / `beat` / `shop` / `rest` / `recruit` / `quarterReview` で、入力なしにフェーズ・選択・資源が変化しない。
- カウントダウン、自動決定、リアルタイム層と同じ進行圧が無いことをユニットまたはE2Eで固定する。

既存仕様の検証追加が中心であり、難易度は**低**。

### RI-34 ローカル完結の将来拡張

外部API・共有バックエンドは対象外。着手時に個別IDへ切り出す。

- ツール別シナリオ
- 組織シナリオ共有（ローカルファイル／文字列による入出力）
- 組織診断ダッシュボードの時系列・部門比較
- 四半期レビューの高度化

カードデッキの研修方針、デイリーラン、AI導入失敗図鑑、レビュー地獄リプレイ、「なぜ燃えたか」は実装済み。社内LT／経営プレゼンモードと外部サービス連携は対象外。

## 2. 確定した判断

- Zustandは要件ではない。`RunEngine`を状態の正本とし、決定論、保存、リプレイ、UI同期を満たせばよい。
- 巨大組織は表示用の合成チームではなく、独立状態を持つ複数チームとして扱う。
- カード、レリック、進化ノードのSPEC内の具体例は方向性であり、実装データとの差を許容する。
- カードはラン外のコレクション画面で一覧・解放状況を確認できるようにする。

## 4. バックログ運用

- IDは`RI-NN`の連番とし、欠番を再利用しない。
- ミューテーション改善はエピック`RI-{N}`（再ベースラインごと）と実装単位`RI-{N}-{GROUP}{SEQ}`（1PR = 1 GitHub Issue）に分ける。採番・進捗の正本はGitHub Issueとし、本ファイルへ番号予約や状態台帳を置かない。方針は[mutation-remediation.md](./mutation-remediation.md)を参照する。
- 状態は`未着手`、`進行中`、`保留（要判断）`、`完了`を使う。
- 1項目は原則1PRで完了できる大きさに分割する。エピックは受入条件と分割順を記載する。
- 完了時は個別節を削除し、上の完了要約と[spec-mapping.md](./spec-mapping.md)を更新する。
