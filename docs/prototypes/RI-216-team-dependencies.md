# RI-216: チーム間の依存を支援先選びへ反映する

対象 #612 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と依存契約

通常ランから隔離した純TS試作。seed `RI-216` は盤面識別子で乱数は使わない。チームは platform / product / incident の3つ。依存は2本で、product の `feature` と incident の `followup` が platform の `gate` を前提にする。`hot` は incident の独立した仕事で、期限 tick 2 を過ぎて完了すると価値6が0になる。

1期間に支援は1チームへ1工数。支援先に対象の仕事がなければ、その期間は空振りとして数える。チームは支援がない限り自分では進まない。完了した前提は同じ期間の下流を解放しない。下流が対象になるのは次の期間からで、同じ期間に複数チームへ支援しても、期間開始時の対象だけが進む。したがって支援を渡す順序では残工数も成果も変わらない。

閲覧は記録するだけで工数・価値・期限を変えない。閲覧していないチームへの減点はない。全体能力を下げる係数は持たない。

## 同条件比較

| 盤面 | 上流を先に解く | 危機の独立仕事を先に終える |
| --- | ---: | ---: |
| 期末3 | 1 | 6 |
| 期末4 | 9 | 7 |

差引は納品した価値の合計。費用や敗北状態は置かない。期末3では上流を2期間かけても下流が1工数しか進まず、価値は前提の1だけになる。同じ3期間で危機の独立仕事を終えると価値6。期末4では上流を終えた次の期間から feature を2工数進め、価値1+8=9になる。危機を先に終えてから前提へ移ると6+1=7で、feature は期末の外に残る。

依存を2本抱える platform へ常に支援する方針は、期末3では危機支援に負ける。依存の多い場所を機械的に選ぶだけでは済まない。差引が低くても敗北にはしない。全期間を待っても成果0のまま終われる。

固定工数の仮説比較であり、本番の面白さや一般的優位の証明ではない。次は受動的な自チーム処理、支援の分割、followup まで届く期末、期限の感度を見る。
