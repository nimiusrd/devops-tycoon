# RI-285: 記録された昇格に人物の一言を添える

対象: [#681](https://github.com/nimiusrd/devops-tycoon/issues/681)、親 #548、関連 #537。四半期レビューの声（#640）とは別のスプリント結果画面。

## 判断と限定採用

プレイヤーは直近スプリントで誰がどのランクへ昇格したかを振り返り、既存のドラフト・四半期レビューへ進む。

**既存の昇格記録から導出する表示を限定採用する。** 人間によるプレイ評価は未実施で、人物への愛着、振り返りの有用性、継続意欲は未評価。Issueはopenのまま、その評価と次の判断条件を残す。マージやE2Eの成功を面白さの証明とは扱わない。

比較対象は「既存の成長一覧」と「同じ一覧に任意の一言を添える構成」。一言を常時出すと結果カードが過密になるため、既存の `result-details` を使い、成長一覧の末尾に初期状態で閉じた入口だけを追加する。読むには開く操作が増える代わりに、評定・診断・休職・介入分析・継続操作の既存表示を維持する。新たなゲーム上の利益・代償はない。

## 正本・順序・再閲覧

- 対象は `GrowthOutcome.promotions` のみ。ID、記録当時の名前、昇格先を同じエントリから読み、`promotionVoicesView` が「ミドル／シニアに昇格しました。」を導出する。現在のロスター、感情、担当実績、プレイヤーの育成意図は補わない。退職・改名後も記録の名前を使う。
- 記録配列の順序を保ち、1ページ最大3人。4人目以降も「次の3人」「前の3人」で全員を再閲覧できる。同姓同名は記録IDで区別する。
- 閉じて再び開くと同じページを表示。別の昇格記録に変わると先頭ページ・閉じた状態へ戻る。ページ位置と開閉状態は保存しない。
- 記録なし・空配列では入口と台詞を出さない。レベルアップ、休職、文書増加から昇格を推測しない。旧保存・旧リプレイの欠落も同じ扱い。
- ページ移動と開閉はHTML内の表示状態のみ。時間、操作回数、警告、介入結果、資源、判定、乱数を変更しない。結果のスクロール内に置き、既存の継続ボタンを使う。別モーダルや自動送りは追加しない。
- 保存スキーマ、恒久履歴、ruleset、通常simを変更しない。記録フレームから同じ一言を再導出する。

色・ボタン・フォーカス・折りたたみは既存の `--text-dim`、`.btn`、`.result-actions`、`.result-details` を再利用する。新しい意味の色・共有寸法・motionはない。Pixiの変更と複数画面の視覚変更はないため、Pixiスナップショット更新・galleryは対象外。

## 再現条件と機械検証

ゲームルール、係数、資源は変更しない。表示前後で同一の状態と入力列を比較する。乱数・勝率・固定戦略のスコア比較はこの表示変更に該当しない。

- ユニット: seed `ri285-promotion-save` / easy の実エンジンを初期化し、保存対象スナップショットへ記録を固定する。記録にだけ存在する人物、改名前の名前、同姓同名、ミドルとシニアを検証。JSON往復、保存再開、リプレイ復元と旧記録欠落を照合し、入力が不変であることを確認する。
- E2E: seed `ri285-promotion-e2e` / easy。公開APIで開始・スプリント開始・pause、実WebGLの準備完了後に `step(1_000_000)` で結果へ進む。表示用fixtureとして成長なし／昇格0人／1人／4人と休職1人を固定する。4人のIDは `record-1`〜`record-4`、昇格先はミドル・シニア・ミドル・シニア。先頭は長い名前、後ろ2人は同姓同名。ロスターを「現在のロスター名」に変更しても過去発言に補わない。自然なプレイで4人同時昇格へ到達した証拠とは扱わない。
- 入力列: 一言なしを確認 → 1人を開く → 4人へ切替 → Enterで開く → 次ページ → Spaceで閉じる → Enterで再開 → 前ページ → 継続。表示操作前後で `getState()` 全体が一致し、休職表示・介入分析へスクロールでき、最後はドラフトへ進むことを確認する。
- viewport: 320×568、390×844、768×1024、1024×768、1440×900のそれぞれ通常／reduced motion。閉じた入口の高さ、キーボードフォーカス、長い名前の折り返し、横はみ出し、固定継続操作を確認し、開閉前後の画像を添付する。
- リプレイ: 同じ結果フレームをJSON往復してIndexedDBへ保存し、再読込後も当時の名前を表示。`lastGrowth`を欠落させた旧フレームでは入口なし。ジャンプ先がない場合の継続無効・理由表示を維持する。
- 既存の実ランE2Eで、ボス結果→四半期レビューと危険行の表示を確認する。

```sh
devcontainer exec --workspace-folder . npm test -- tests/unit/render/promotionVoicesView.test.ts tests/unit/ui/sprintResultInteractions.test.ts --maxWorkers=1
devcontainer exec --workspace-folder . npx tsc -b
devcontainer exec --workspace-folder . npm run lint
devcontainer exec --workspace-folder . npm run format:check
devcontainer exec --workspace-folder . --remote-env PLAYWRIGHT_PORT=5681 npm run test:e2e -- tests/e2e/promotion-voices.spec.ts tests/e2e/boss-sprint-result.spec.ts tests/e2e/sprint-result-quarter-goal.spec.ts --workers=1
```

実行結果はPRに記録する。

## 残条件

人間が同じseed・easy・資源・入力列で、入口を閉じた構成と開いた構成を比較し、誰が昇格したかを思い出しやすいか、当時の記録だと分かるか、警告確認・継続を妨げないかを評価する。有用性が低ければ文言・位置・3人というページ上限を再試作する。

休暇・過労・復帰の台詞、恒久的な経歴帳、発言選択・報酬は今回の採用範囲外。実際の節目記録と人間評価が揃った時点で別途判断する。
