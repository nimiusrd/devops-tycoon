### RI-135 組織診断ダッシュボードの深掘り

SPEC第23章は、ズーム階層本体に加えて時系列トレンドや部門間比較の深掘りを残している。部門現在値比較（RI-125）と完了四半期の診断・KPI時系列（RI-128）は実装済みで、業界ランキングの他社趨勢は演出値のままとする判断済みである。残る深掘り（チーム単位比較、指標切替、部門トレンドの追加系列など）は複数の有効な選択肢があり、選択で変更範囲が変わるため、範囲を決めてから実装する。

受入条件:

- 深掘りの対象（比較単位、指標、操作）と非対象（他社趨勢の実履歴化、外部ダッシュボード）を本項目または確定判断へ書き、実装PRはそれに従う。
- 全社マップの既存比較表・四半期トレンドを壊さず、sim・保存・勝敗を変えない表示追加に留める。
- 表示は状態を読むだけで、DOM / Pixiの両方で主要viewportのレイアウト契約を維持する。

### RI-136 F-9 有効手集合の完全計測

### RI-137 Fast Refresh警告の解消

`npm run lint`は成功するが、`src/ui/replayContent.tsx`と`src/ui/responsiveMode.tsx`がコンポーネント以外の値・関数・Hookもexportしているため、`react-refresh/only-export-components`警告が5件出る。実行時の不具合ではないため、完了済み計画書の整理とは分けて扱う。

受入条件:

- Providerコンポーネントと、定数・resolver・Hook・contextの所有ファイルを分離し、公開importと挙動を維持する。
- `npm run lint`が警告なしで成功する。
- リプレイのコンテンツスナップショット解決とレスポンシブ境界の既存unit／E2Eテストが成功する。

### RI-138 balance:checkの手書き差分誤検知

`scripts/check-balance.mjs`は`docs/probability-model.md`全体を生成物として`git diff`へ渡すため、生成対象外の手書き説明だけを正しく変更した場合も`npm run balance:check`が失敗する。CIではコミット済み差分が基準になるため表面化しないが、コミット前検査としては偽陽性になる。

受入条件:

- コマンド実行前後の内容、または生成管理範囲だけを比較し、手書き領域の意図的な作業ツリー差分を許容する。
- 代表曲線の端点や生成Markdown／SVGが古い場合は引き続き失敗する。
- cleanな作業ツリー、手書き領域だけの変更、生成領域が古い変更をテストで区別する。

## 2. 確定した判断

- Zustandは要件ではない。`RunEngine`を状態の正本とし、決定論、保存、リプレイ、UI同期を満たせばよい。
- 巨大組織は表示用の合成チームではなく、独立状態を持つ複数チームとして扱う。
- カード、レリック、進化ノードのSPEC内の具体例は方向性であり、実装データとの差を許容する。
- カードはラン外のコレクション画面で一覧・解放状況を確認できるようにする。
- 診断・KPI時系列（RI-128）は四半期境界でセーブへ明示永続化し、業界ランキングの自社趨勢だけ実履歴化する。他社趨勢は演出値のままとする。
- ステークホルダー別交渉（RI-130）は既存7種へ交渉相手と、信頼差以外の提示条件（予算・次期目標・組織状態・次期予算上限・次四半期物理）を足す。対話ツリーや新しい GoalAdjustmentId は追加せず、`availableAdjustments()` の除外条件と効果量は変えない。
- 複数四半期ロードマップ（RI-131）は表示専用の見通しとする。sim・保存・勝敗を変えず、未達で継続可能な四半期レビューに Q+1 / Q+2 を出す。物理キャリーは次の1四半期だけのまま。拘束力ある Q+2/Q+3 約束は対象外。
- バランスパラメータSSoT（RI-104）は子課題 RI-105〜124 の完了により親エピックも完了とする。AI依存モデルの意味変更と係数確定はRI-134で完了した。
- RI-134 は`manualCapability`を導入しない。`W`は既存のリテラシー・習熟・ドキュメントから導出し、プレイヤー判断は AI 前提ワークフローの組み込みとする。AI なし実装による能力回復、個人単位への拡張、タスク担当者は対象外とする。係数は64 seedの統制Monte Carloと既定コホートで確定し、ルールセットv4へ反映した。
- F-9 有効手集合の完全計測は評価容量の問題であり、合否ゲートは RI-132 で実装済み。未計測を解消または対象外と決めるまで[RI-136](#ri-136-f-9-有効手集合の完全計測)で追跡する。

## 4. バックログ運用

- IDは`RI-NN`の連番とし、欠番を再利用しない。
- ミューテーション改善はエピック`RI-{N}`（再ベースラインごと）と実装単位`RI-{N}-{GROUP}{SEQ}`（1PR = 1 GitHub Issue）に分ける。採番・進捗の正本はGitHub Issueとし、本ファイルへ番号予約や状態台帳を置かない。方針は[mutation-remediation.md](./mutation-remediation.md)を参照する。
- 状態は`未着手`、`進行中`、`保留（要判断）`、`完了`を使う。
- 1項目は原則1PRで完了できる大きさに分割する。エピックは受入条件と分割順を記載する。
- 完了時は個別節を削除し、上の完了要約と[spec-mapping.md](./spec-mapping.md)を更新する。
