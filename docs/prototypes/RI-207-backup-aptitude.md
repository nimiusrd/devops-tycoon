# RI-207: 代打の実績からReview適性を発見する

対象: #603。#601 / RI-205の予定不在モデルに依存するスタック第2段。評価: **修正して継続、本番統合は保留**。純TSの固定シナリオ比較であり、通常の編成画面・自然成長・保存・リプレイ・rulesetは変更しない。

## 同条件の編成と判断

seed `RI-207`、公開された40工数、6期、主力m2が2〜5期に休暇、6期に復帰。全戦略は同じロスター・能力・スタミナ・仕事・期限から始まる。控えm1は準備期に稼働しない。

- 代打なし: 主力のいる1/6期だけ処理し、不在中は待つ。
- 控え起用: 2期にm1をReviewへ配置。不在中の実績でReview適性を発見する。
- 経験者起用: 2期にCoding担当m3をReviewへ配置し、即時の処理能力を借りる。経験者へ適性報酬は付けない。

両代打は復帰後もReviewを担当する固定編成。起用は開始期の一度だけで、以後に別配置や休職となった場合は自動でReviewへ戻さない。プレイヤーが代打を外す戦略でも、済んだ実績は残り、その後の実績は増えない。

## 実績・限定効果・一度だけの発見

対象は固定の控えm1、能力はReviewのみ。配置や起用操作に報酬はない。予定不在が実際に適用された期間中、m1自身が処理した正の工数を人物ID・期・量で保存する。少なくとも2稼働期、累計6工数の両条件を満たした期末に、Review能力を最大10増やす（上限100）。当期の処理量は増やさず、次の期から能力へ反映する。

仕事なし、体力0、休職、控え配置では処理せず実績も得ない。1期で6工数以上を処理しても期間条件を満たさない。主力復帰後の処理は不在実績に数えない。発見は人物ID・発見期・実増分を保存し、以後は再報酬化しない。復帰後のプレビューでも同じ発見が確認できる。全期間境界でJSON再開を比較する。

この試作の「成功」は実際にレビュー工数を処理したこと。誤レビュー・手戻り・個別仕事の品質成功は別モデルであり、適性の根拠として未評価。全員へ隠れた適性を割り当てたり、順番に起用して報酬を集めたりする仕組みは作らない。

## 採否と次の比較
