## 目的

ローグライクの周回構造を完成させる。1ラン＝1四半期。マップ→スプリント→リザルト→ドラフト→進化の入れ子を通しでプレイできるようにする。

## タスク

- **フロー（XState）**: マップ → スプリント → リザルト → ドラフト → 進化 の入れ子（第3章）
- **ランマップ（第4.4章）**: 分岐ルート、ノード種別（通常/高負荷/イベント◇/ショップ$/休息☾/ボス★）
- **ボススプリント（第10章）**: 大型リリース / 本番大規模障害 / セキュリティ監査 / 経営レビュー（特別ルール）
- **組織進化ツリー（第4.5章 / 第11章）**: 進化ポイント割り振り、5ブランチ（開発力 / レビュー体制 / 品質保証 / AI活用 / 文化）
- **組織文化レリック（第8章）**: 恒久パッシブ（心理的安全性、ポストモーテム文化 等）
- **ランダムイベント（第9章）**: 良い / 悪い / ネタ + 分岐選択イベント（トレードオフ）
- **組織タイプ診断（第13章）**: Healthy Acceleration / Review Hell / AI Overproduction / Rework Spiral / Senior Sacrifice / Documentation Kingdom
- **称号と勝敗（第4.6 / 第14 / 第15章）**: 称号付与、勝利条件（通常 / 健全 / AI導入成功 / 経営 / 現場幸福 / カオス / ノーダメ）、敗北条件
- **メタ進行（第17章）**: ボス撃破で解放、localStorage 保存
- **難易度（第16章）**: Easy / Normal / Hard / Nightmare + 試練モディファイア
- **画面ステート演出（第18.3章）**: 健全=昼 / Review Hell=赤く夜 等

## 描画移行の判断点（第22.4）

粒数・ノード数が増えるため、**ここで盤面描画を PixiJS + pixi-viewport へ移植**する。sim を分離済み（[phase-1](./phase-1-sprint-simulation.md)）なら移植コストは小さい。[phase-5](./phase-5-org-scale.md) の巨大組織はこの移植を前提とする。

## 成果物

1ランを最初から最後（ボス）まで通しでプレイでき、結果で解放が進む。

## テスト

- Vitest: 進化ツリー / レリック / イベント効果の状態反映、診断ロジック、勝敗判定、seed 固定のラン再現
- Playwright: 島 / ノードクリック → 画面遷移、ボス突破フロー

## 完了の目安（DoD）

マップ→ボス→解放まで通しプレイでき、診断 / 称号 / 勝敗が機能する。
