# RI-255: 経営要求の追従と一回の条件交渉を比べる

対象 #651 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定イベント

通常ランから隔離した純TS試作。seed `RI-255` は盤面識別子で乱数は使わない。要求は選択前に順で分かる。1番はAI利用で、作業tick2までに6を満たすと12。2番はレビュー待ちで、作業tick3の終わりに上限1以下なら12。変えてよい条件は2番の上限だけで、6まで緩める交渉を1回できる。交渉の信頼消費は8で、既存の四半期レビューへは課金しない。交渉すると、期末に残ったレビュー待ちを次期の約束として別記し、得点からはもう一度引かない。

処理は1tickに3。追従は期限の早いAI利用を先に埋め、達したあとレビュー待ちを減らす。交渉も作業順は同じで、上限だけを最初に緩める。2回目の交渉は拒否する。達成の呼び方は、AIとレビューの結果から `both` / `ai-only` / `review-only` / `neither` を決める。目指す称号の入力は持たない。開始直後の敗北にはせず、四つの結果はどれも継続できる。

盤面はAI利用がレビュー待ちを増やすかだけが違う。両立は1のAI利用が待ちを増やさない。矛盾はAI利用1につき待ちが1増える。閲覧は、要求順、期限、上限、緩和後の上限、信頼消費、既存レビューへ課金しないこと、両方の得点と結果種別と次期の約束を選択前に示す。決定後の選択肢は空になる。

## 同条件比較

得点は、達成した要求の価値から信頼消費を引いた値である。次期の約束は得点に入れない。

| 盤面 | 要求へ追従 | 上限を1回交渉 |
| --- | ---: | ---: |
| AI利用が待ちを増やさない | 24 | 16 |
| AI利用が待ちを1増やす | 12 | 16 |

待ちが増えない盤面では、追従が両方を達成して24になる。交渉も両方を達成するが信頼8を払い16になる。待ちが増える盤面では、追従はAI利用12だけを取り、期末の待ち3が上限1を超えて12になる。交渉は上限6で待ち3を通し、両方の24から信頼8を引いた16になる。残った待ち3は次期の約束で、得点からは引かない。追従が常に上位ではない。どちらの方針も継続でき、敗北にはしない。

固定2盤面の仮説比較であり、本番の経営レビューの証明ではない。次は、追従がAIとレビューへ枠を同時に分けると、矛盾盤面でも交渉を上回るかを見る。

## 本番境界と検証

通常ランの exec-review、ステークホルダー交渉、四半期レビュー、自動勝利、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。勝利種別は結果から決める試作内の分類であり、本番の勝利種別へは接続しない。閲覧順で結果は変わらない。version 1の信頼済み内部JSONに比較の初期状態、入力列、得点の推移を含める。外部入力検証と通常保存互換は対象外。

`exec-demands-comparison.json` に盤面、初期状態と入力列、得点の推移を記録した。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
