# RI-234: 機能の保守と新規開発の割当を比べる

対象 #630 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と保守

通常ランから隔離した純TS試作。seed `RI-234` は盤面識別子で乱数は使わない。余力は4。期間は3。機能は api、screen、billing で、完成に必要な作業は各4、完成価値は6。RI-228 の完成判定を使い、必要量を超えた分は捨てる。保守は完成した次の期間から、その機能の単価だけ増える。同じ機能へ再度作業を入れても完成は一度だけで、保守は増えない。未消化の保守は技術的負債や障害とは別の不足として数える。敗北状態にはしない。

軽い観測の保守単価は1、不足1あたりの減点は1。重い観測の保守単価は2、不足1あたりの減点は4。閲覧は単価、罰則、機能ごとの残り作業と保守、今期の義務を示す。

成長を急ぐ手順は、毎期すべての余力を未完成の機能へ入れる。体制を先にする手順は、今期の義務までを保守へ入れ、残りを未完成の機能へ入れる。義務が無い期間は両方とも新規開発になる。余った作業は他の機能へ移さない。未完成の機能が無いときは api へ入れるが、今回の期間内では起きない。

## 同条件比較

得点は完成価値から、不足×罰則を引いた値である。次期余力は、期末に見えている保守義務を余力4から引いた値である。

| 観測 | 急ぐ完成 | 急ぐ得点 | 急ぐ次期余力 | 体制の完成 | 体制の得点 | 体制の次期余力 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 保守が軽い | 18 | 15 | 1 | 12 | 12 | 2 |
| 保守が重い | 18 | -6 | -2 | 12 | 12 | 0 |

軽い観測では、急ぐ15が体制12を上回る。不足は3で、次期余力は1である。体制は不足0、次期余力2で、完成は api と screen の12にとどまる。重い観測では、急ぐと3機能の完成18に対して不足6、得点-6、次期余力-2になる。体制は完成12、不足0、次期余力0で得点が上回る。どちらの観測でも、急ぐ方が短期の完成価値は高い。

固定2観測の仮説比較であり、本番の人員計画の証明ではない。次は保守単価、完成に必要な作業、罰則の感度を見る。

## 本番境界と検証

通常ランの流入、技術的負債、障害、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。閲覧順で結果は変わらない。本番採用時は機能ごとの保守開始時期の保存と、負債・障害との分離を別Issueに分割する。version 1の信頼済み内部JSONに比較の初期状態と入力列を含める。外部入力検証と通常保存互換は対象外。

`feature-upkeep-comparison.json` に観測、初期状態と入力列、得点と次期余力を記録した。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
