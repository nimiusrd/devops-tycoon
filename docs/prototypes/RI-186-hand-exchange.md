# RI-186: 集中力を払うスプリント中の手札交換

対象: #582、親: #548。判断: **施策を採用し、本番統合へ進める**。初期ルールは集中力2、1スプリント最大2回。採否の記録は #582。

## 判断と最小試作

現行の `dealHand`、`playCardFromHand`、`applyAction`、`stepSprint` を利用する隔離モデル。手札の指定位置1枚を捨て札へ移し、山札先頭1枚で置換する。交換費用は集中力2、上限はスプリント当たり2回。山札枯渇時の再シャッフルはしない。山札順はseedで開始時に確定し、交換では乱数を消費しない。必要施策の確定ドローやカードの強化は行わない。

停止、完了、盤面枯渇後の下限tick待ち、上限到達、手札なし、山札なし、不正なインデックス・重複、集中力不足では、費用・カード・乱数・交換回数を変えない。発動済みカードは交換対象にならない。交換しただけでは組織基準値・効果を適用しない。引いたカードは既存の発動処理で一度だけ適用する。

交換前に全カード山が対象カードの完全かつ一意な分割であることを検証し、交換対象以外の重複・欠落・範囲外も拒否する。試作保存の任意項目 `sprintDeckIndices` で持ち込み対象を保持でき、未指定の既存JSONは全所持カードを対象とする。対象リスト自体の不正・重複も拒否する。

## 同じseed・資源での比較

seed `RI-186`。6枚のデッキ、手札3枚、初期集中力8。カードはレベル1の既存定義。定型16件を全件Coding中／Review待ちに置き、8tickの短い締め切りまで処理する。これは短時間の比較盤面であり、通常ランの尺・流入・WIP配置を再現したプレイテストではない。

共通入力は「先頭カードを0/1/2回交換→先頭1枚を発動→残集中力で毎tick割り込みレビューを試す」。引いたカードに合わせた最適化はしない。初期手札はレビューBot、自動テスト、PRサイズ制限。1回交換ではCopilot、2回ではドキュメント整備を引く。操作前にこの結果をプレイヤーへ保証しない。

## 通常ランでの評価と採否

64 seed・各28件を通常の流れで処理する条件を使い、交換なし／1回／2回を比較した（計192ラン、全ランで28件完了、タイムアウトなし）。固定方針での平均出荷は交換なし320.906、1回316.953、2回318.594。平均差はそれぞれ-3.953、-2.313で、交換を常に使うだけでは出荷改善を確認できなかった。一方、プレイヤーが状況を見て手札と現場介入の機会費用を比べる選択肢として採用する判断を得た。採用は機能の判断であり、交換が平均成績を上げるという保証ではない。

初期ルールには既存試作の費用2／上限2を採用する。次のプレイテストでは、出荷だけでなくシニアHP・負債・現場介入の余地を確認し、必要なら費用と上限を再調整する。

## 本番統合

通常ランから呼び出せる `RunEngine.exchangeCard()` とゲーム操作APIを追加する。交換対象は未発動の手札1枚。集中力2を支払い、カードを捨て札へ送り、山札先頭のカードを同じ手札位置へ入れる。成功時だけ交換数を増やし、最大2回で停止する。交換しただけではカード効果を適用せず、山札が空のとき捨て札を再シャッフルしない。交換では乱数を消費しない。

DeckBarから交換モードを選び、交換対象を選択できる。費用・残り山札・回数を表示し、停止中、集中力不足、山札切れ、上限到達では交換を無効にする。交換回数をスプリント結果へ含め、リプレイの結果スナップショットでも参照できる。ゲーム結果に影響するルール追加に合わせてバランスルールセットを更新する。

## 検証

本番統合の画面確認対象はスプリントの手札操作UI（320×568、390×844、768×1024、1024×768、1440×900）、交換モードと通常モード、停止・集中力不足・山札切れ・上限到達。動的盤面は変更せずPixi描画への変更はない。
