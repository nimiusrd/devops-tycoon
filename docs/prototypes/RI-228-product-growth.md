# RI-228: 同じ作業量でも、完成した機能の構成を比べる

対象 #624 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と機能完成

通常ランから隔離した純TS試作。seed `RI-228` は盤面識別子で乱数は使わない。製品は1つ。機能は api、screen、billing で、各必要量は5。完成したときだけ価値8を一度足す。期間は3、余力は4。必要量を超えた投入は捨て、他の機能へ移さない。未完了の進捗は機能を増やさない。敗北状態にはしない。

運用へ1以上を置かない期間は、障害対応が要る盤面だけ事故6を足す。余力がある盤面の事故は0。集中は一つの機能を完成させてから次へ進む。分散は3機能へ同時に置く。運用枠は毎期間1を運用へ置き、残りを集中と同じ順で進める。

## 同条件比較

差引は完成価値−事故。

| 盤面 | 集中 | 分散 | 運用枠 |
| --- | ---: | ---: | ---: |
| 余力あり | 16 | 8 | 8 |
| 障害対応が要る | -2 | -10 | 8 |

余力ありでは集中の16が、分散8と運用枠8を上回る。集中と分散の機能への投入はどちらも12で、完成は api と screen、api だけに分かれる。障害対応が要る盤面では運用枠の8が、集中-2と分散-10を上回る。機能を揃える余力と事故を止める余力は同じ4を分け合う。

固定3機能の仮説比較であり、本番の面白さや一般的優位の証明ではない。次は必要量、完成価値、事故の感度を見る。
