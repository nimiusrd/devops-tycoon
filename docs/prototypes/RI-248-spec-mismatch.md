# RI-248: 認識違いを確認・作り直し・説明・範囲縮小で比べる

対象 #644 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定イベント

通常ランから隔離した純TS試作。seed `RI-248` は盤面識別子で乱数は使わない。対象は決済フロー1件。開始前の兆候は未確認の仮定で、仮定のまま4工数進めると認識違いが一度だけ発生する。確認2工数を先に終えると認識違いは起きない。

確認後の本実装は6工数、納品価値18。作り直しも残作業6、納品価値18で、先に進めた4工数は戻らない。説明は合意作業2、納品価値12で、合意作業を終えたときだけ合意済みになる。範囲縮小は残作業1、納品価値7。価値も残作業も名前だけを変えた同じ効果にはしない。1期間の処理は1。納品できないまま期限を迎えても敗北にしない。

盤面は期限の工数だけが違う。余裕は8、中間は6、逼迫は5。閲覧は、対象、兆候、確認工数、発覚までの仮定工数、3対応の残作業と価値、4方針の得点を選択前に示す。決定後の選択肢は空になる。

## 同条件比較

得点は納品価値だけである。未納品は0。

| 期限 | 先に確認 | 作り直し | 説明 | 範囲縮小 |
| --- | ---: | ---: | ---: | ---: |
| 8 | 18 | 0 | 12 | 7 |
| 6 | 0 | 0 | 12 | 7 |
| 5 | 0 | 0 | 0 | 7 |

期限8では確認が本実装を終えて18になる。作り直しは同じ価値18でも合計10工数で、この期限では残作業2のまま0。期限6では確認の本実装が残作業2で0、説明が合意まで終えて12。期限5では説明の合意が1工数残って0、範囲縮小だけが7になる。確認を常に最大化する方針は、期限6と5では上位にならない。

この3期限では作り直しは確認と同じ納品価値で残作業が多く、単独では勝たない。固定期限の仮説比較であり、本番の仕様確認の証明ではない。次は期限10で確認と作り直しが同じ18になる条件と、確認自体の費用を見る。
