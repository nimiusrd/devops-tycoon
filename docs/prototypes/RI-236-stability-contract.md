# RI-236: 安定契約の確保と新機能投資を比べる

対象 #632 / 親 #548。結論: **再試作、本番統合保留**（初回は限定比較の仮説採用、下記の感度追試を追加）。人間のプレイ評価は未実施。

## 固定盤面と契約

通常ランから隔離した純TS試作。seed `RI-236` は盤面識別子で乱数は使わない。顧客は RI-229 の keeper 1層で、人数は4。余力は4。期間は3で、3期間を終えると報酬は止まる。無期限の収入にはしない。契約は1件。毎期2を安定へ入れると報酬4が一度入る。2未満は違反で、軽い観測の損失は1、厳しい観測の損失は10である。機能は api、screen、billing で、完成に必要な作業は各4、完成価値は12。RI-228 の完成判定を使い、余った作業は他の機能へ移さない。敗北状態にはしない。

閲覧は確保枠、報酬、違反の損失、完成価値、現在の予算と残り作業を示す。閲覧では期間も予算も動かない。同じ期間の達成を二度報酬にしない。余力を全部安定へ入れても報酬は4のままである。

安定重視は毎期ちょうど2を契約へ入れ、残りを未完成の機能へ入れる。新機能重視は毎期すべての余力を未完成の機能へ入れ、契約は守らない。

## 同条件比較

予算は、完成価値、期間報酬、違反の損失を反映した期末の値である。

| 観測 | 安定の予算 | 安定の完成 | 新機能の予算 | 新機能の完成 | 新機能の違反 |
| --- | ---: | --- | ---: | --- | ---: |
| 違反が軽い | 24 | api | 33 | api, screen, billing | 3 |
| 違反が厳しい | 24 | api | 6 | api, screen, billing | 3 |

安定の予算推移は4、20、24で、報酬は3期間とも一度ずつ、違反は0である。軽い観測の新機能は11、22、33で、完成3つが違反1×3を上回る。厳しい観測の新機能は2、4、6で、同じ完成3つでも違反10×3のため安定の24を下回る。

固定2観測の仮説比較であり、本番の継続課金の証明ではない。

## 確保枠・期間報酬・違反損失の感度比較

2026-11-17追試。結論は **再試作、本番統合保留**。初回の反転に加え、同点と確保枠による完成件数の段差を確認できた。ただし固定方針の経済計算であり、人間の面白さ、適応的な配分、継続意欲は評価していない。

`stability-contract-sensitivity.json` に21条件・42運営の初期状態、実効係数、全入力、予算推移、成果と費用、隣接サンプルでの優劣変化を保存する。seed `RI-236` は引き続き識別子で、乱数は使わない。同一条件の二運営は同じ初期状態から開始する。余力4・3期間・各機能の必要作業4・完成価値12・顧客4人・初期予算0は固定。初回の比較JSONと既定係数は維持する。

安定重視（`steady`）は毎期確保枠と同じ量を保守へ、新機能重視（`rush`）は保守0とし、残りを api → screen → billing の先頭の未完成機能へ入れる。方針は固定し、確保枠の変更にだけ配分を連動させる。完成に余った作業は他機能へ回さず捨てる。途中の進捗に予算価値は付けない。戦略の探索・最適化は行わない。

各列で表の固定係数から一つだけ動かす。`initial.board = calm` は既存試作との共通ラベルであり、実効係数は各点の `rules` と `initial.reserve/reward/penalty` を正とする。

| 列 | 固定する係数 | 変える値 | 安定予算 / 新機能予算（値の順） | 同点・反転 |
| --- | --- | --- | --- | --- |
| reserve-calm | 報酬4、損失1 | 確保枠0, 1, 2, 3, 4 | 48/48, 24/33, 24/33, 12/33, 12/33 | 0は同一配分による同点。正の枠では新機能優位 |
| reserve-boundary | 報酬4、損失5 | 確保枠0, 1, 2, 3, 4 | 48/48, 24/21, 24/21, 12/21, 12/21 | 2→3で安定優位から新機能優位へ反転 |
| reward | 確保枠2、損失1 | 報酬0, 4, 6, 7, 8 | 12/33, 24/33, 30/33, 33/33, 36/33 | 6で新機能優位、7で同点、8で安定優位 |
| penalty | 確保枠2、報酬4 | 損失0, 1, 3, 4, 5, 10 | 24/36, 24/33, 24/27, 24/24, 24/21, 24/6 | 3で新機能優位、4で同点、5で安定優位 |

確保枠1・2の安定重視は api 1件を完成し、3・4は完成0件。新機能重視は正の確保枠で3件完成・3回違反となる。確保枠0は両方とも3件完成・3回達成の境界ケースで、契約を破る代償がない。0での同点を選択の面白さの根拠にはしない。

確保枠1と2では予算推移はいずれも `[4,20,24]` だが、支出の内訳は異なる。1では保守3、機能投入9、受理7、破棄2、未完成進捗3。2では保守6、機能投入6、受理6、破棄0、未完成進捗2。確保枠3・4では予算推移 `[4,8,12]`、未完成進捗は3・0。比較JSONの `accounting` はこの機会費用と、完成価値・報酬収入・違反損失を分けて記録する。

報酬を r、損失を p とすると、確保枠1・2での「安定予算−新機能予算」は `3(r+p)-24`、3・4では `3(r+p)-36`。したがって同点はそれぞれ `r+p=8` と `r+p=12` で、和が大きい側で安定重視が優位になる。整数の確保枠2→3では完成価値が12下がるため、報酬4・損失5の列は同点を通らず反転する。未観測の小数枠の同点を推測しない。ユニットでは確保枠0〜4、報酬・損失各0〜12の845条件も式と照合する。

全42運営で、各入力前に閲覧しても状態が変わらないこと、全入力の再生と毎入力後のJSON保存再開が同じ状態になること、保存再開後も同じ方針が同じ入力を選ぶことを確認する。3期間後は報酬・違反・完成を再計上しない。予算が負でも敗北は追加しない。

### 再現方法

リポジトリルートからDev Containerで比較JSONを生成する（Node 24、既存のViteを使用。package.jsonにスクリプトは追加しない）。

```sh
devcontainer exec --workspace-folder . node --input-type=module -e 'import { createServer } from "vite"; import { writeFileSync } from "node:fs"; const server = await createServer({ server: { middlewareMode: true } }); try { const { compareStabilityContractSensitivity } = await server.ssrLoadModule("/src/prototypes/stabilityContract.ts"); writeFileSync("docs/prototypes/stability-contract-sensitivity.json", JSON.stringify(compareStabilityContractSensitivity(), null, 2) + "\n"); } finally { await server.close(); }'
devcontainer exec --workspace-folder . npx prettier --write docs/prototypes/stability-contract-sensitivity.json
devcontainer exec --workspace-folder . npm test -- src/prototypes/stabilityContract.test.ts --maxWorkers=1
```

次の再試作は、期間途中の配分変更と報酬確定時点を人間が理解して選べるかを、遊べる文脈で評価する。終了条件は、事前に契約の達成・違反を予測でき、完成機会との交換を説明できること。今回の数値から本番値や採用を決めない。人間評価の設計・実施と、その結果に基づく採否が残るため #632 はオープンで追跡する。

## 本番境界と検証

通常ランの予算、信頼、自動勝利、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。継続収入は3期間で止める。閲覧順で結果は変わらない。本番採用時は契約期間と、期間内の報酬を一度に限る保存を別Issueに分割する。version 1の信頼済み内部JSONに比較の初期状態、入力列、予算推移を含める。外部入力検証と通常保存互換は対象外。

`stability-contract-comparison.json` と感度比較JSONに観測、初期状態と入力列、予算推移を記録した。試作の状態形状はversion 1のまま、係数は既存のreserve/reward/penaltyフィールドに保存する。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
