# RI-215 メンバー固有の介入を温存する

対象は #611。判断は **再試作**。高価値PRがキューのどこに並ぶかで、レビュー鬼の切り札を使う時期が変わった。編成で誰を Review に置くかに加え、その人の一手を今の渋滞と後の山場のどちらに使うかがプレイヤーの判断になる。

## 誰が何に使えるか

Review に配置された稼働中の「レビュー鬼」だけが、Review 待ちの高価値PRを1件指定して先に審査できる。試作の担当者は初期シニア `m2`。本人の ID と PR の ID を指定し、`checkPriorityReview` で対象と発動可否を読める。休職中、控え、本人の不在、対象外のトレイトやPR、集中力3未満、本人のスタミナ12未満では発動できない。成立しない入力は盤面・資源・乱数の消費位置を保持する。

成立時は集中力3、本人のスタミナ12、本人につきラン中1回の使用枠を支払う。審査は通常の `reviewOne` を使い、共通のシニアHP消費、点火・手戻り・出荷、コンボの判定を受ける。審査が通らなかった場合も費用を支払う。成立による運用安定・連携ゲージの付与はなし。試作状態の使用済みリストに人物IDを記録し、再配置で更新されるメンバー情報と別に保持する。再配置、JSONからの再開、新しいスプリントの開始を経ても同じIDの残数は0。

## 固定条件と操作

- seed は `RI-215:1`〜`RI-215:8`。ロスターは `:roster`、前半と後半の盤面と乱数列はそれぞれ `:early`、`:later` を同じ seed に足して生成する。標準の初期組織を使い、AI導入フラグはオフ、シニアHP100、AIリテラシー45、スタミナ95から開始。通常の初期編成の補正を使う。前半の組織とロスター、使用記録を後半に引き継ぐ。
- 前半と後半はそれぞれ Review 待ち8件、集中力5、初期連携ゲージ・コンボ0。全て人手のPRで、7件は定型、1件は高価値。前半は通常規模の高価値PRが末尾（ID 7）。後半は複雑な高価値PRを末尾（ID 7）または先頭（ID 0）に置く。
- 各盤面の tick 0 に選んだ介入を1回だけ入力する。優先レビューは高価値PRを指定し、既存介入は `applyAction` の既定対象を使う。tick 1・2 は `stepSprint` で進め、期限までに Done に着いたものを集計する。未完PRは別案件を表す後半に持ち越さない。成長・スプリント間休息・デッキ・ボス固有ルールは試験条件に含めていない。
- 処理した PR が変わると点火や手戻りに使う乱数の順番も変わる。同じ seed の初期条件から始める固定方針の比較として扱う。

## 次の判断条件

今回はUIと人間のプレイ評価は未実施。次の試作では後半のキュー予兆が見える操作を用意し、発動前に本人・対象・代償・残り回数を読み取れるか、差し迫った期限と余裕のある期限で使用時期を選び分けられるかを人間のプレイで確かめる。流入と自然なスタミナ回復がある盤面でも優先レビューと既存介入の使い分けが成立すること、レビュー鬼を外す編成に価値が残ることを採用判断の条件とする。

本番統合を判断する際は #536 の8介入の固定位置と即時介入の1回操作を前提に、発動の入口と結果表示を設計する。通常ランの保存・再開には使用済みID、リプレイには発動 tick・人物ID・対象IDを持たせる方針とし、ルールセットと旧保存データの互換、試作の固定回数と費用を再評価する。今回の試作は `src/prototypes/` 内から実シムを呼び出し、JSON再開の検証は試作状態に限る。
