# RI-282 流入停止後のレビュー滞留回復

対象は #678、親課題は #548。判定は**再試作**。アンドンを選んだ場面で、実際に新規投入が止まり、その後にレビュー滞留が解消したかを確かめる。プレイヤーが集中力と士気を使って目先の着手を譲る判断を、後の盤面と一緒に振り返れるかが仮説。待機すれば投入とレビューを続け、介入の費用を温存できる。

## 試作実績の条件

1. 選択直前のレビュー待ちが既存アンドンの渋滞判定以上。現行は10件以上。
2. tick 0でアンドンが発動し、持続中に未着手タスクと空き実装枠があるtickで投入が止まる。持続中に未着手件数が減る記録は矛盾として未判定。
3. 観測終了時に開始時のレビュー待ちの半数以上が出荷されている。レビューから手戻りへ移った件数は出荷に含めない。
4. 観測終了直前の3 tickすべてでレビュー待ちが5件以下。最後の1 tickだけ下がった場合は条件未達。

表示案は「アンドンで新規投入を停止。その後、レビュー待ちが5件以下で3 tick続き、開始時にレビュー待ちだった12件のうち10件を出荷」。対象の件数は記録から埋める。説明の範囲はこの順序で観測した出来事まで。同じ盤面を待機で進めても回復する例がある。レビュー処理の結果には既存アンドンの安定化、流入順、乱数消費順、自然回復が重なるため、回復した件数をアンドンの単独効果として数えない。

判定APIは試作専用形式の版、現行ルールセット、決定、40 tickの連続観測を照合する。旧セーブ、欠けた観測、異なるルールセットは未判定。通常リプレイのキーフレームから観測値を補間しない。判定は渡された試作記録に基づくため、JSONの作成者や真正性は確認できない。

返すのは試作実績の成立、回復の有無、投入が止まったtick。普通のメタ・実績定義・デイリー報酬・通常ラン保存には接続しない。何度判定しても報酬は増えない。採用を検討する際は、通常ランへの記録統合と実績の一度限りの取得を別途設計する。
