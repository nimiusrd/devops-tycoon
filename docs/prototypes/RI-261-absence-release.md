# RI-261: 主力の予定不在に備えるリリース

対象: #657。#610 / RI-214の知識引き継ぎを使うスタック第2段。評価: **修正して継続、本番統合は保留**。

## 固定シナリオと準備の予告

seed `RI-261`、既存ロスターの専門家m2と後継者m1、レビュー対象40工数。準備前のperiod 0で本人ID、不在開始2、復帰6、期限6を公開する。1期の準備後、不在期間は2〜5期（半開区間 `[2,6)`）。6期は復帰して最終処理する。新しいボスは通常抽選へ追加しない。

`previewAbsenceRelease` が対象者・期間・残量・準備費用・能力増分の開始時期を返す。予定不在は別データとして保存し、疲労休職の `onLeave` は変更しない。不在開始時に担当とAI配布を記録して控えへ移し、復帰時に元の配置へ戻す。人物の削除・再生成はしない。休職中なら予定不在が終わっても控えを維持する。

## 三つの判断と費用

- 通常準備: 既存能力で公開済みの仕事を処理する。
- 前倒し: 準備期の通常処理後に専門家が最大3工数を追加処理する。追加工数ごとにスタミナ2を使う。残量・体力が足りなければ追加量を減らす。
- 引き継ぎ: 準備期に専門家の余力3、後継者の余力1を譲る。既存師弟試作でレビュー力を10増やし、不在が始まる翌期から能力4工数/期として働く。

出荷は同じ40工数を実際に減らした量だけ。前倒しの成果をボス開始時に再加算しない。通常処理の実工数と育成に使った余力に対してスタミナ1を消費する。前倒し追加分だけ単価2とし、通常疲労へ別の回数罰は足さない。不在中は毎期5まで回復し上限を超えない。自然成長・昇格・確率的休職は模擬しない。

通常処理と育成の確定前に、人物別の残りスタミナの整数部分を当期余力の上限へ渡す。専門家3・後継者1の育成費用を両者が払えない場合は教えず、払える範囲の通常処理だけを行う。不在中は毎期の処理前に控え配置を維持するため、保存後に編成を変更しても主力は稼働しない。元配置は不在開始時の記録を復帰まで維持する。

## 採否と次の条件

予告と準備の代償・不在中の能力を分けて示す仮説は成立した。ただし今回の期限では前倒しの総成果が上回り、全準備で未処理が残る。係数を調整して採用とせず、**修正して継続**とする。次は不在期間の長短、前倒し可能な仕事と当日到着の仕事の分離、危機時の優先配分、主力の低体力・後継能力上限を比較する。本番の勝敗基準・通常抽選・全ボス実績への追加は別Issueで決める。

通常ランの固定トラック、保存、リプレイ、rulesetは変更しない。試作専用version 1にseed生成後の人物状態、開始/終了期、復帰前配置、育成台帳、残量、消耗と回復履歴を保存する。全期間境界でJSON再開の一致を検証する。期限後の再実行は状態を進めず、復帰・出荷を二重適用しない。本番統合時には予定不在と疲労休職の優先順位、休暇回復式、入力履歴・保存互換を別実装単位で設計する。
