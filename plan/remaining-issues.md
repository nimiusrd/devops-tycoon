# プロジェクト残課題リスト

`follow-ups.md`（実装後フォローアップ）と `mockup-parity.md`（モックアップ乖離・SPEC 未充足の
横断バックログ）を統合した、プロジェクトの残課題の一覧。
実装後に繰り越した未解決事項・改善候補・判断点と、`mockups/` のデザイン基準（第22.2）や
`SPEC.md` の企画に対して**まだ届いていない／暫定のままの項目**、および**遊んでみて見えてきた
設計再検討（SPEC からの変更提案）**を一本化して追跡する。

> 実装済み機能とコードの対応・充足状況は [spec-mapping.md](./spec-mapping.md) §1 の対応表、
> 未充足箇所の一覧は同 §2 に集約している。本ファイルは「繰り越し・未解決のやること」に絞る。

> 複数領域にまたがる繰り越しは「横断テーマ（A〜F）」へ集約し、各領域の節からは「→ 横断テーマ X」で
> 参照する。画面のモックアップ乖離は §1、SPEC 未充足は §2、バランス調整は §3、ループ設計の再検討は
> §3.5、技術構成は §4、領域固有の細かな繰り越しは「領域別の繰り越し」へ整理する。

優先度の目安: **優先度:高=体験の核に直結 / 優先度:中=見栄え・整合 / 優先度:低=将来拡張**。

## 横断テーマ（複数領域共通）

単一の領域でなく複数領域にまたがる繰り越し。各領域別節からは「→ 横断テーマ X」で参照する。

### A. バランスのモンテカルロ許容レンジ化（統計テスト基盤）

**該当: スプリント / キャラクター育成 / 組織スケール / メタ進行 / 四半期レビュー**（§3 と対応）

代表 seed のモンテカルロで主要メトリクスを許容レンジ化する統計テスト基盤を整え、各領域の暫定値・
効果係数の回帰確認に使う。基盤は全体で統一する。

- **優先度:中 スプリント**: スプリント結果の主要メトリクス（Delivered / Rework / Incidents / Senior HP /
  Review Queue Peak）に許容レンジを持つ統計テストを追加する。
- **優先度:低 キャラクター育成**: 編成差がスプリント結果に与える影響レンジを、代表 seed のモンテカルロで
  許容レンジ化する。
- **優先度:中 組織スケール**: 全社/部門レバーの効果係数（`src/data/levers.ts`、暫定）を許容レンジ化する。
- **優先度:中 メタ進行**: メタ解放のコスト（`UNLOCK_DEFS` / `src/data/unlocks.ts`）、`applyRunReward` の
  points 配分（勝利20 / 敗北5 × `scoreMul`）、デイリー固定条件（難易度 normal・試練なし）の暫定値を後続調整する。
- **優先度:中 四半期レビュー**: 目標修正の代償（`src/data/goalAdjustments.ts` の `trustDelta` / `budgetDelta` /
  `goalEffects` / `orgEffects`）と `evaluateQuarterOutcome`（`src/sim/run/quarterReview.ts`）の outcome 閾値
  （信頼・予算・士気・Senior HP・missedCount）を許容レンジ化する。あわせて目標生成（`buildQuarterGoal`）も。

### B. PixiJS スプライト化・適用範囲の拡張

**該当: スプリント / 周回・育成・診断 / キャラクター育成 / WebGL 移行**（§1-A・§4 と対応）

全社マップは `?renderer=pixi` で Pixi 化済み（WebGL 移行で完了）。残るのは盤面・キャラ系のスプライト化と
他レイヤへの拡張。

- **優先度:低 スプリント**: キャラ/タスク粒は現状 SVG/DOM。スプライト＋プール（`render/iso.ts`）へ寄せ、
  粒の工程間移動アニメや延焼の連鎖演出を強化する（演出の詳細は §1-A）。
- **優先度:低 周回・育成・診断 / キャラクター育成**: PixiJS 移行ゲートの管理。現状は粒数・ズーム階層が
  増えていないため DOM/SVG を継続するが、破綻し始めたら前倒しする。キャラクター育成のキャラ表情
  （💪😩😴🙂）も移植時にスプライト表現（疲れ顔/ガッツポーズ等）へ拡張する。
- **優先度:中 WebGL 移行**: 現状は全社マップのみ。部署ビュー／現場盤面など他レイヤへ Pixi を広げるかは
  未着手（粒数・ズーム階層が DOM/SVG の限界に近づいたら検討）。スプライト＋プールは `render/iso.ts` を供給先に。

### C. 業界ランキングとメタ進行の接続

**該当: 組織スケール / メタ進行**（§2 と対応・優先度:中）

デイリーのベストは `meta.dailyRuns` に保存され Title / RunResult には表示されるが、業界ランキングビュー
（`IndustryScreen`）へ「自分のデイリー記録」を差し込む擬似リーダーボードは未着手。シーズン/リーグ/
デイリーラン（同一シード）を `state/meta`（第17章）へ恒久反映するかを判断する（現状はラン内の集約から
都度生成）。

### D. 称号（`WinType`）の永続化

**該当: 周回・育成・診断 / メタ進行**（§2 と対応・優先度:中）

勝利種別をラン結果表示だけで終わらせず、称号/実績コレクションとして保存・閲覧できる形にするかを判断する。
メタ進行は最小実装として実績 ID コレクションに留め、勝利種別ごとの達成有無の永続記録・一覧化は未実装。
実績コレクションで十分か、称号を別軸で持つかを決める。

### E. 診断別・継続不能種別ごとの画面演出

**該当: 周回・育成・診断 / 四半期レビュー**（§2 と対応・優先度:中）

現状の昼/曇り/地獄系トーンを、6つの組織タイプ診断（Healthy Acceleration / Review Hell /
AI Overproduction / Rework Spiral / Senior Sacrifice / Documentation Kingdom）それぞれの色・背景・
警告文へ拡張する（周回・育成・診断）。あわせて `missed_crisis` / `reorg_required` / `shutdown` の終了演出は
共通の `lose` 系に集約しているため、継続不能の種別ごとに診断・演出を分けるかを判断する（四半期レビュー）。

### F. メタ進行への解放対象の拡張

**該当: 周回・育成・診断 / キャラクター育成 / メタ進行**（§2 と対応・優先度:低）

現状のメタ解放はカード／レリックのみ。初期カード・初期レリック・メンバー／トレイト解放（初期メンバー/
トレイト）・追加イベント・追加試練など、ボス撃破で解放される対象を増やすかスコープ外として明記するかを
判断する（周回・育成・診断／キャラクター育成／メタ進行で同根の課題）。

## §1. ゲーム画面のモックアップ乖離（最優先テーマ）

「数字は動くがモックアップのゲーム画面から離れている」問題。メイン画面（スプリント盤面）はアイソメ俯瞰
オフィスへ刷新済み（PR #38）。残るのはズーム階層（第4.7〜4.11）の3画面と、メイン画面の演出残務。
スプリント盤面で確立した手法を全社マップ→部署ビュー→業界ランキングへ横展開するのが最短（→ 進め方の指針）。

### §1-A. スプリント盤面の演出残務（実装済みの上積み）

メイン画面はアイソメ俯瞰オフィスへ刷新済み。以下は「より mockup / 第18章に近づける」上積み。

- **優先度:中 タスク粒の工程間移動アニメ**: 現状は各工程に「山」で静的配置。mockup の「ベルトコンベアで
  流れる粒」「AI暴走時に高速で Review に突っ込む」までは未実装。粒の流れ（補間移動）を入れる。
- **優先度:中 延焼の連鎖演出**: 炎上タスクが隣へ燃え広がる／緊急対応成功で爽快に消火、の連鎖アニメ（第18.2）。
  現状は炎上ドットの flame 表示まで。
- **優先度:低 キャラ/粒のスプライト化**: 現状 SVG/DOM。PixiJS 移植時にスプライト＋プール（`render/iso.ts`）へ

### §1-B. 全社マップ（org-screen）の等角化 — 優先度:高

- **現状**: 島の配置は `render/iso.ts` のアイソメ投影で決まるが、チームは**フラットな矩形カード**。
  `?renderer=pixi` で全社マップのみ Pixi 切替可だが、既定 DOM も Pixi も mockup の見た目には未到達。
- **目標（`mockups/org-screen.png` / 第4.8）**: 浮遊する**等角プレート**＋部門ゾーン（縦ストライプの色分け）
  ＋**チーム島**（ミニ机＋アバター＋AIボット）＋中央の**共通基盤ハブ**（サーバーラック＋ボット）＋
  **チーム間フローの等角レーン**（詰まると赤熱）＋規模効果バッジ。健全/渋滞/Review Hell の状態色。
- **規模感**: 中〜大。スプリント盤面と同じ手法（純シーン計画＋SVG/Pixi 描画）で島・ハブ・レーンを等角化。
  `OfficeRoom`/`OfficeActors` 相当の「島アクター」を作る。

### §1-C. 部署ビュー（dept-screen）の等角化 — 優先度:高

- **現状**: アイソメ未使用のフラット表現。

## §3.5. ゲームデザインの再検討（SPEC からの変更提案）

遊んでみて見えてきた、ループ設計そのものの課題。SPEC の記述を変える提案を含むため、実装前に方針合意が要る。

### §3.5-A. ノード選択（ランマップ）の廃止とイベント判定化 — 優先度:高

> **設計詰め済み**: 具体仕様は [run-loop-redesign.md](./run-loop-redesign.md)（四半期トラック＋
> 混合ビート＋組織状態重み付け）。合意済みの方針: 判定＋選択の混合 / 組織状態で重み付け /
> 高負荷・ショップ・休息は選択イベントに統合。次は同ドキュメント §7 の段階移行で実装する。

- **課題**: メイン画面（ラン中）はノード選択（ランマップ）が大半を占める。戦略的要素はあるが、
  **状況をコントロールできすぎている**。Slay the Spire は「リターンを得るためにリスクを取る」
  トレードオフ設計だが、現状はノード選択に**明確なリターンが無い**ため、結局**リスクの無い選択肢を
  取るだけ**になり、意思決定が形骸化している。
- **提案（主案）**: **ノード選択を廃止**し、従来ノードを選んでいたタイミングで**何らかのイベント判定**
  （確率/状況依存のイベント）が起きるようにする。プレイヤーが盤面を完全制御するのではなく、
  「次に何が来るか」に対処する緊張感を戻す。
- **影響範囲（SPEC）**: 第3章 基本ループ図、第4.4 ランマップ画面（分岐ルート）、第9.4 分岐選択イベント、
  第10章 ボススプリントへの到達構造。`src/sim/run/map.ts`・`RunMapScreen`・`runMachine` の `map`/`enterNode`、
  `window.game.enterNode` の公開契約に波及する大きめの変更。
- **論点（実装前に決める）**:
  - イベント判定の中身: 完全ランダムか、組織状態（渋滞/負債/士気/AI依存度）依存の重み付きか。世界観の
    制約（第2.1）に収める。
  - リスク↔リターンの担保: もしノード選択を一部残すなら、各選択に**明確なリターンとそれに見合うリスク**を
    付ける（代替案B）。主案（完全廃止＋イベント判定）と代替案B（ノードにリスク/リターンを持たせる）の
    どちらを採るか。
  - ボス/四半期末への到達: マップ廃止後、ボススプリント（第10）や四半期レビュー（第8）へどう接続するか
    （固定スプリント数＋途中イベント、等）。
  - 決定論: イベント判定は seed 付き PRNG に載せ、デイリーラン/リプレイ/テストを保てるようにする（第22.3）。

## 領域別の繰り越し（個別）

横断テーマ・§1〜§4 に集約しきれない、各実装領域固有の繰り越し。横断課題へは「→ 横断テーマ X」で繋ぐ。

### スプリントシミュレーション

- AI あり/なしの差分が seed 固定で安定して観測できる代表 seed を記録し、バランス調整時の回帰確認に使う。
- **アクションバーのマスコット**: 介入アクションバーのマネージャー像（mockup footer）は未移植。
  必要なら `ActionBar` へ追加する（§1-A と同件）。
- → 横断テーマ **A**（主要メトリクスの統計テスト）・**B**（キャラ/粒のスプライト化）。

### 能動操作とカード

- 介入アクション全種について、成功/失敗理由、集中力消費、クールダウン、副作用のテーブル駆動テストを追加する。
- カード強化はショップ/休息ノードで接続済みかを確認し、強化対象選択 UI が必要なら「周回・育成・診断」の
  繰り越しへ送る。
- コンボ/連携ゲージの表示と実効果が乖離しないよう、UI 表示値と sim 集計値を同一 seed で検証する E2E を追加する。

### 周回・育成・診断

- **ランダムイベントの不足補完**: `tone: joke` のネタイベントを最低 1〜2 件追加し、良い/悪い/ネタの分類が
  UI とテストで確認できるようにする。

## 進め方の指針

§1（画面のモックアップ乖離）が「数字は動くがゲーム画面に見えない」という当初課題の本丸。スプリント盤面で
確立した手法 ——「純シーン計画（`*Scene.ts`、Vitest 検証）＋ SVG/Pixi 描画アダプタ＋設計座標空間の % 配置」——
を全社マップ→部署ビュー→業界ランキングへ横展開するのが最短。Pixi 移植（§4 / 横断テーマ **B**）はこの
等角化と歩調を合わせる。バランス調整（§3 / 横断テーマ **A**）は統計テスト基盤の整備とセットで進める。
