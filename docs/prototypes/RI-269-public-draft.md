# RI-269: 候補と予算を事前公開するドラフト決戦

対象: [#665](https://github.com/nimiusrd/devops-tycoon/issues/665)、親: #548。判断: **再試作**。人間のプレイ評価は未実施。試作のマージを本番採用・Issue完了とは扱わない。

## 仮説と契約

抽選への対応とは別に、既知の監査へ高額札1枚に集中するか、安価札を組み合わせるかを準備段階で選ぶ。取得予算は6の1枠だけで、通常ショップの価格・ラン予算・メタポイントとは独立する。発動時には別途、既存カード定義の集中力を払う。

| 固定候補（全てレベル1） | 試作での取得費 | 発動focus | 主な利益・代償 |
| --- | ---: | ---: | --- |
| シニア採用 | 6 | 4 | 品質+12・レビュー容量×1.3。予算を使い切る |
| 自動テスト | 5 | 3 | 品質+10・障害率×0.8、実装速度×0.95 |
| ドキュメント | 3 | 2 | 品質+5・障害率×0.9、実装速度×0.92 |
| レビューBot | 3 | 3 | レビュー効率×1.2、品質は上がらない |
| PRサイズ制限 | 2 | 2 | レビュー効率×1.15・手戻り率−0.05 |
| Copilot | 1 | 2 | 実装速度×1.15・定型×1.3、依存+5・セキュリティ−5 |

全効果係数は比較JSONの `contract.offers.effects` に記録する。表の数値は本番バランスの提案ではない。

`viewPublicDraft()` は開始前から全6候補・各価格・発動focus・取得済み・残予算・ボスの全突破条件を返す。UIは追加していない。候補の取得は確定で、研修方針・レアリティ重み・メタ所有による抽選は行わない。通常メタで未解放のシニア採用・レビューBotも、この挑戦中だけ貸与する。恒久解放・通常コレクションへの書戻しはない。

準備中は購入・取消・一括変更が可能。取消手数料は0で全額返金し、一括変更は取消と再購入を原子的に行う。予算超過・重複・未知候補は全体を拒否し、費用・乱数・履歴を変えない。同じ札を再購入して強化することはできない。開始後は完了後も変更・取消・再開始不可。再挑戦は新しい専用状態を作る。

現在の価格では取得できるのは最大3枚なので、取得札は全て手札へ確定配布し、山札抽選も行わない。所持順は候補一覧順に正規化する。購入時・開始時にカード効果は付けず、手札から発動したときだけ適用する。発動済み札の再発動は拒否し、既存のbaseline台帳も維持する。

## 実simの比較条件

実装は `src/prototypes/publicDraft.ts` に隔離する。RI-186 `handExchange` とRI-187 `sprintLoadout` の、既存カード発動・工程進行と乱数位置保存を参照した。通常の `createSprint` / `playCardFromHand` / `applyAction` / `stepSprint` / `summarizeSprint` を使い、固定値による独自採点は行わない。

既存ボスはセキュリティ監査1件。定義のタスク倍率1・障害倍率1と、`evaluateBoss` の品質50以上・負債40以下・時間切れ不可を使う。通常ラン全体の編成・四半期KPI・報酬・敗北判定までは再現しない。`bossCleared` はこの隔離した監査条件の評価である。

標準組織・AI有効、初期品質45・負債0、集中力8、16タスク、期限60tick・最短完了0。タスクの種別・価値はseedから生成し、Backlogから通常のWIP制限を通して流す。全組織値とスプリント設定は各行の `initial` に保存した。同じseedの各ビルドは同じ仕事と乱数開始位置を使う。カードにより工程・乱数消費の分岐が変わることは成果の一部とする。

seedは `RI-269` / `RI-269:1` / `RI-269:2`。simのseed文字列は `ri269-public-draft-v1:<seed>:sprint`。3条件×3seed×5構成の45ランを比較する。感度は一度に1要因のみ変更し、`quality-pressure` は初期品質40、`short-deadline` は期限24tick。他は対照と同一。

固定入力方針は、選んだ札を下表の順にtick0で全て発動し、各tickで緊急炎上なら緊急対応、それ以外でReview4件以上なら割り込みレビューを試す。他は工程のみ進める。不成立の介入は無消費で、そのtickの工程は進む。固定方針の比較であり、人間が盤面を読んで適応する行動ではない。

| 構成 | 発動順 | 取得費 | カード発動focus |
| --- | --- | ---: | ---: |
| 集中 | シニア採用 | 6 | 4 |
| 分散 | ドキュメント→PRサイズ制限→Copilot | 6 | 6 |
| テスト | 自動テスト→Copilot | 6 | 5 |
| 工程 | レビューBot→PRサイズ制限→Copilot | 6 | 7 |
| 未準備 | なし | 0 | 0 |

未準備も同じ介入方針を使う。準備を省いた瞬間には敗北せず工程を続ける。品質が足りないため監査突破はできないが、seed `RI-269:1` は20tickで全16件を完了する。

## 成果と代償

対照のseed別結果（`出荷 / 完了tick / 消費focus / 監査`）。focusは発動と介入の合計で、取得費と合算しない。

| 構成 | RI-269 | RI-269:1 | RI-269:2 |
| --- | --- | --- | --- |
| 集中 | 157 / 60 / 8 / 時間切れ | 194 / 19 / 7 / 突破 | 186 / 59 / 8 / 突破 |
| 分散 | 160 / 60 / 7 / 時間切れ | 170 / 26 / 6 / 突破 | 208 / 45 / 7 / 突破 |
| テスト | 176 / 47 / 8 / 突破 | 195 / 18 / 8 / 突破 | 180 / 59 / 8 / 突破 |
| 工程 | 156 / 60 / 8 / 時間切れ | 173 / 22 / 7 / 品質未達 | 202 / 60 / 8 / 品質未達 |
| 未準備 | 158 / 60 / 4 / 時間切れ | 194 / 20 / 3 / 品質未達 | 179 / 60 / 4 / 時間切れ |

集中と分散は取得費が同じ。seed `:1` では集中が24pt多く7tick早い代わりにfocusを1多く消費し、seed `:2` では分散が22pt多く14tick早くfocusも1少ない。分散の「複数札を取れる」ことだけで優位は決まらない。テスト構成も全ての出荷比較で上回るわけではない。

初期品質40では分散は品質45となり、完了したseed `:1` / `:2` でも監査未達へ変わる。集中は品質52、テストは50を維持する。期限24ではseed `:1` の集中19tick・テスト18tickが突破する一方、分散は158ptで時間切れになる。seed `:2` は全構成が時間切れ。品質条件を満たすだけで突破と判定していない。

全入力列、出荷、完了数、時間切れ、品質、負債、HP、炎上・延焼、発動札、介入回数、focus、取得費、最終乱数位置は [public-draft-comparison.json](./public-draft-comparison.json) に保存し、対象テストが再計算と全件照合する。再生成:

## 保存・境界と隔離

専用 `version: 1` / `ri269-public-draft-v1` の保存はseed・条件・成立した入力列・現在のsim乱数位置をJSONで持つ。復元時は同rulesetから実simを再実行し、乱数チェックポイントを照合する。組織・カード山・baseline台帳・クールダウン等も再構築する。通常セーブや通常リプレイへの取り込み口は作らない。現状の係数に依存する試作保存であり、sim係数変更時は専用rulesetを更新して旧保存を拒否する必要がある。本番向けの長期互換形式ではない。

未知version/ruleset/条件、無効な入力、二重購入・開始・発動、予算超過、完了後tick、乱数破損は拒否する。失敗操作は履歴にも残さない。準備・進行・完了で保存再開し、同じ続きの入力で状態・成果・乱数が一致することを検証する。

通常ラン・DraftScreen・研修方針・メタ・通常スコア・報酬・通常リプレイ・rulesetは変更しない。試作はRunEngineやUIから呼ばれず、プロジェクトの実simを利用するだけである。

## 採否と次の判断

**再試作**。準備の選択が実工程の出荷と費用へ影響し、seed・品質・期限で集中と分散の結果も変わることを確認した。ただし公開候補の選択自体を人が理解して楽しめるかは未検証で、最適戦略や本番係数も決められない。3seed・1ボス・固定介入方針に限る結果であり、通常ランへ統合しない。

次は専用の操作可能な試作で、候補6枚・取得費と発動focus・変更と全額取消・監査条件を見て、人が異なる構成を選ぶ理由と結果の理解を評価する。初回は品質45と40を予告して比較し、「品質余裕を買うか、複数札と介入余力を取るか」を説明でき、結果から再構築を選べるかを終了条件とする。その結果で採用・候補価格の再調整・見送りを判断する。人間評価が済むまで #665 はopenのままにする。
