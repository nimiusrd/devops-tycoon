# RI-301 リプレイの判断注釈

親: #548 / Issue: #697（元案149）

## 判断と今回の範囲

プレイヤーは保存済みランの一場面を選び、なぜその判断を選んだかを説明して共有する。見る人は記録された結果と作者の説明を分けて読み、別案を考える。

既存リプレイ一覧に、フェーズ境界を選ぶ欄・任意の1000 UTF-16コード単位までの本文・保存を追加する。1リプレイ1場面を対象とし、空欄保存で削除する。既存JSON書出し・取込み・閲覧UIまで統合する。任意tick、連続ハイライト、複数注釈、因果の自動推定は今回扱わない。

## 既存ルールと保存契約

- 通常ランの初期資源・seed・固定トラック・費用・勝利種別の自動判定・報酬を変更しない。注釈の編集はsimへ入力せず、ゲームRNGを消費しない。
- ReplayBlob v2に任意の`annotation`（注釈形式version 1）とキーフレームIDを付加する。ゲームrulesetは変えない。旧v1/v2の読込み・正規化ではIDを生成しない。初回の非空注釈保存でUUIDを一度だけ生成して永続化し、以後は保持する。
- 注釈はreplay IDと場面IDを参照する。場面の並べ替え・別場面削除で移動しない。重複ID・対象の欠落・他replayへの参照・未対応版・上限超過は読込み時に拒否する。本文はReactテキストとして表示する。
- 編集開始時の記録と端末の記録を同一IndexedDBトランザクションで比較する。別タブの更新・削除は競合として既存の通知経路へ渡す。ファイル取込みにも同じ比較を適用する。保存失敗は既存の保存状態へ通知し、編集欄の下書きとエラーを残す。
- 元リプレイが未保存の場合は、既存の保存再試行を先に案内する。保存先に無いことを別タブの削除と取り違えない。
- 比較基準は、表示用キャッシュとは別に保存先から実際に読めた一覧を保持する。未保存完走の退避JSONを同じタブへ取り込む復旧を妨げない。注釈の失敗分は元の比較基準ごと再試行キュー・退避JSONへ残し、共通バナーで再試行する。再試行中に編集した新しい下書きは保持する。比較基準を持たない通常完走・移行の書込みも、既存の注釈を無条件に置換しない。
- 復旧の照合情報はゲームセッション側にも保持し、一覧を開き直した後も自分の再試行だけを編集基準へ反映する。空の永続先への途中移行も実際に書いたスナップショットと比較して再更新し、他タブが変えた内容は置換しない。注釈のロールバックでは、他タブが削除した対象を復活させない。
- 書込み後の読込みとロールバックが共に失敗しても、再試行で保存先が自分の意図した記録と完全一致するか照合する。異なる記録を上書きせず、一致すれば重ねて書かずに復旧する。明示的なJSON取込みが成功したIDでは古い注釈の再試行・復旧情報を破棄し、取り消した注釈を編集欄へ再表示しない。
- セッション限りの保存先では、端末に保存できたと表示しない。注釈と補助IDはRI-291の同一条件判定、RI-299の同内容重複排除には含めない。

## 検証条件

ユニットでは実RunEngineの開始フレームと実parserを使い、旧形式・JSON往復・ID安定・削除/並べ替え・不正入力・メモリ/IndexedDB双方の競合・公開APIの保存失敗を検証する。RI-299の固定方針実ランにも注釈を付け、結果・重複判定が同じことを確認する。

ブラウザではseed `annotation-e2e`、easy、試練なし、カード取得・購入なし、イベント先頭選択・休憩回復の固定入力で実際に完走したリプレイを使う。勝敗やスコアを手入力しない。5 viewport（320×568 / 390×844 / 768×1024 / 1024×768 / 1440×900）で編集・保存・ファイル往復・HTML安全表示・実WebGL閲覧・キーボード・reduced motionを確認する。保存失敗と2タブの競合を別ケースにする。

注釈は非ゲーム情報であり、係数比較や複数seedの強さ評価は不要。固定入力は保存・表示契約の再現条件であり、楽しさや人間の適応の証拠にはしない。

実測の初期資源・ルールセット・入力方針・成果は [`replay-annotations-validation.json`](replay-annotations-validation.json) に残す。通常の自動判定はシニア体力による敗北、出荷6199pt、25境界だった。注釈追加・JSON往復でこの結果は変わらなかった。E2Eの出力には注釈付きの完全なJSONと各viewportの実画像も残す。

検証は標準Dev Container（Node v24.16.0）で実行。対象ユニットでは旧リプレイ・各画面・ゲーム内容の同一性を確認。最終の保存・共有・UI接続関連5ファイル243件（注釈18件、既存の保存復旧130件を含む）が成功。`replay-annotation.spec.ts` と `replay.spec.ts` は2並列16件成功。5 viewport、通常/reduced motion、Tab/Shift+Tab/Enter/Space/Escape、長文のキーボードスクロール、保存失敗・別タブ競合を確認し、実画像も目視した。galleryは16画面を生成し、変更対象の編成・スプリント結果・ドラフト・決着を目視した（既定seedでは四半期レビューに未到達）。Pixi実装・ベースラインは変更していない。

## 採否と次の条件

**再試作**。既存経路へつながる最小統合を用意し、保存・共有・閲覧の技術契約を検証する。人間プレイ評価は未実施であり、本番採用・Issue完了とはしない。

次は人間が実ランの場面を選び、理由を書いて第三者へJSON共有し、記録値と説明の区別・場面選択の分かりやすさ・別案の議論に役立つかを評価する。1場面制限と1000文字上限が十分かを確認して採用範囲を決める。細粒度記録へ広げる場合は別の記録設計として判断する。
