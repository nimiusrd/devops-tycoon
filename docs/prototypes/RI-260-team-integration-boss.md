# RI-260: 承認記録の異なる2チームの統合

対象 [#656](https://github.com/nimiusrd/devops-tycoon/issues/656) / 親 #548。判断: **再試作**。今回の独立期間モデルは比較材料として残す。本番採用は決めていない。人間のプレイ評価は未実施。

## 検証する判断と境界

共同作業の待ちを減らすために今すぐ規約を揃えるか、演習をしながら共同案件だけを試すか、現場規約を維持して二重台帳を払い続けるか。プレイヤー価値の仮説は「移行を急いだ代償と、併存を長引かせた代償を実際の案件から判断できる」こと。既存機能の修正ではなく新ルールの比較試作である。

- `standardProcedure`（RI-227 / #623）は規約と仕事の**適合**、横断支援の費用を扱う。本件は適合出荷を加減せず、相互作業の受け渡し・移行完了・習熟と手戻りを扱う。
- `pilotRollout`（RI-226 / #622）は**施策の対象範囲の展開**。本件のpilotは共同案件の承認記録だけを先に揃え、betaの現場規約を残す。その間の二重台帳と指導・演習を実際の工数で払う。未知効果や一斉事故の抽選はない。
- #538 の委任・全社期間契約には接続しない。2チームを同一期に一度ずつ進める独立モデルに留め、詳細／粗粒度simの尺度整合や全社報酬を検証済みとはしない。
- 通常sim、部署追加、ボス定義、UI、保存、ruleset、SPECは変更しない。既存の `TeamRunState` を作り直したり、片方の状態を他方へ同期したりしない。

## 初期状態・資源・前提

純TSの信頼済み内部JSON v1。seed `RI-260` は識別子で乱数は使わない。基準6期。alphaは実装が得意で工数6/期・固有仕事の価値2/工数、betaは運用が得意で工数6/期・固有仕事の価値3/工数。両チームの能力、累積固有仕事、習熟は別の状態として保存する。規約統一でも能力と固有仕事の価値は変わらない。

**規約差は承認記録の形式1件のみ**。alphaは書面記録、betaは口頭記録。alphaの書面習熟2、betaは0、上限2。承認権限や階層、文化の良し悪しはモデル化しない。

共同案件6件を1〜6期に1件ずつ投入する。完了条件はalphaの準備2工数、betaの承認2工数、発生済み手戻りの完了。価値は1件12。各チームの残り工数は、そのチーム固有の十分な量の仕事へ使う。共同案件価値と固有仕事価値の和を `deliveredValue` として併記するが、待ち・未完了案件・持越工数・習熟を一つの効用に統合しない。価値12・2・3も試作係数である。

異形式の案件は準備完了の翌期まで受け渡しを待ち、betaが案件ごとに記録変換3工数を払ってから承認する。規約が一致するか、その期の二重台帳を完全に払えば、準備と同じ期に承認へ進める。変換途中で規約が揃った場合、残り変換は不要になる。既に払った時間は返らない。開始済みの承認は、その開始時の形式と手戻りを持ち越す。

書面承認を開始した時点で `(2 − betaの書面習熟) × 手戻り係数2` の追加作業が発生する。承認本体と手戻りを終えた案件だけを完了とし、書面案件完了ごとに習熟+1（上限2）。口頭承認は元から習熟しておりこの手戻りはない。方針を選んだだけで習熟や出荷を増やさない。

## 入力と工数配分

| 入力 | 条件・効果・代償 |
| --- | --- |
| `integrate: immediate` | betaの移行4工数を予約。全量完了後に現場規約も書面へ切替。演習は自動では付かない |
| `integrate: pilot` | betaの共同案件入口の準備1工数を予約。現場規約は口頭のまま。共同案件は書面承認を試す |
| `integrate: coexist` | betaの二重台帳準備2工数を予約。現場・承認とも口頭を維持し、書面との照合を続ける |
| `train` | pilotまたはimmediateで演習を1回予約。alphaの指導1・betaの練習2を同一期に確保できると習熟+1。確保できなければ予約を持越す |
| `expand` | pilot準備完了後に一度だけ残り移行3工数を予約。完了後に現場規約も書面へ切替。即時統一と移行総工数は同じ4 |
| `advance` | 全チームを1期進める。期内の配分と結果を保存 |
| `view` / 閲覧関数 | 時間・工数・習熟・履歴を変えない。返したオブジェクトの編集も元状態へ波及しない |

期内の優先順は移行、演習、二重台帳、共同案件の準備・変換・承認・手戻り、固有仕事。共同案件は投入順。pilot/併存の準備完了後、betaの現場規約が口頭の期間はalpha1・beta2の二重台帳を毎期払う。両者の工数を確保できない期は部分課金せず、共通入口／照合を使えない。書面への移行完了期から二重台帳は不要。

入力で予約した時点では時間を進めず、実際に払った工数だけ台帳へ記録する。費用は固有仕事や共同案件を進める時間と競合するため、成果から二度引かない。終了時の未完了案件、未消化移行、演習予約、発生済み手戻りを残す。投入が期間外の案件も未完了件数に含む。

準備済み未完了の滞留 `unfinishedPeriods`、形式差による翌期待ち `handoffWaitPeriods`、着手可能でもbetaがその案件に全く工数を使えなかった期 `capacityWaitPeriods` を分ける。期末の `waiting` は準備済み未完了件数で、作業中も含む。手戻り工数は別計上する。

未知・重複・終了後・前提未達の入力は無消費で拒否する。方針は一度だけ選べ、pilotの展開と演習時点を変えられる。方針の撤回・台帳運用の中止・チームの増設は未実装。この制約下の固定比較を、プレイヤーの自由な適応と同一視しない。

## 同条件比較と感度

`team-integration-comparison.json` に各ケースの同一初期状態・全係数・入力列・期別の互換/習熟/完了/滞留・成果と代償を保存する。各方針は独立した同一状態から再生する。固定方針は即時統一、pilot（最初の2期に演習を予約して2期後に展開）、当面併存、無操作。無操作は統合作業を払わず、案件ごとの変換と翌期待ちを受け入れる対照。

| ケース | 即時統一 | pilot | 当面併存 | 無操作 |
| --- | ---: | ---: | ---: | ---: |
| 基準: 成果価値 | 162 | 142 | 138 | 141 |
| 基準: 共同案件完了 | 6 | 6 | 6 | 5 |
| 基準: 移行工数 | 4 | 4 | 2 | 0 |
| 基準: 演習工数（指導含む） | 0 | 6 | 0 | 0 |
| 基準: 二重台帳工数（両チーム計） | 0 | 6 | 18 | 0 |
| 基準: 案件別の記録変換工数 | 0 | 0 | 0 | 15 |
| 基準: 実際に払った手戻り工数 | 6 | 2 | 0 | 0 |
| 3期: 成果価値 | 66 | 40 | 66 | 72 |
| 10期: 成果価値 | 282 | 262 | 226 | 258 |
| 二重台帳beta工数0: 成果価値 | 162 | 154 | 174 | 141 |
| 手戻り係数5: 成果価値 | 135 | 133 | 138 | 141 |
| 案件変換工数0: 成果価値 | 162 | 142 | 138 | 186 |
| 共同案件なし: 成果価値 | 168 | 136 | 126 | 180 |

各ケース内で初期資源・需要は同じ。ケース間では期間3/10、移行2/8、手戻り係数0/5、二重台帳beta工数0/4、案件変換工数0、beta能力4を一つずつ変更する。10期でも共同案件は6件のままにし、期間と需要を同時に増やさない。変換工数0の対照でも異形式の翌期待ちは残る。二重台帳beta工数0でもalphaの照合1は残る。さらに開始を3期後へ遅らせる（pilotは開始から2期後に展開）、pilot展開だけを4期後へ遅らせる、共同案件なしの対照を記録した。

基準では即時統一の成果価値が高いが、短期は無操作の固有仕事が残り、二重台帳が軽い場合は併存の値が高くなる。手戻りが大きい場合、即時統一の値は無操作を下回る。pilotは基準の手戻りを6から2へ減らす一方、演習6・二重台帳6を払う。今回の軸ではpilotが成果価値最大の行はない。順位を揃えるために係数を調整していない。二重台帳が重いと承認開始が遅れて演習が先に終わり、手戻りが減るケースもあり、費用を上げると必ず単調に悪化するとは限らない。

共同案件なしで統一しても成果は増えず、無操作は敗北にならない。これらは記録した係数・固定手順の比較であり、一般的順位、組織文化の優劣、面白さ、適応的な判断の証明ではない。

## 採否・次の評価条件

**再試作**。待ち・手戻り・移行・二重運用の支払いを分ける仮説は検証可能になったが、pilotの追加工数を払う判断と、組織の山場としての体験は未検証。Issueをopenで残す。本番採用を見送る結論ではなく、次の不確実性を解くための独立試作として保持する。

次は、需要が途中で変わる同資源シナリオで台帳運用の中止・pilotの継続/展開を選べる小さなプレイ文脈を作る。終了条件は、人間が判断前に「相互作業の前提」「今払う工数」「次に切り替える観測条件」を説明し、終了後に実案件の待ち/手戻りと自分の選択を対応付けられるか記録すること。短期・共同案件の少ない条件も見せ、統一を選ばない判断も成立するか確かめる。参加者数・入力列・説明・迷った箇所を記録し、楽しさは本人の評価として報告する。

pilotの演習はimmediateにも使えるため、次の比較では「即時統一＋同量演習」を必ず含め、pilot固有の価値と演習の価値を分離する。pilotが追加判断として説明できない場合は、規約統合を既存試作へ寄せるか、不要な操作として見送る判断をする。採用時には#538の期間確定・全社集計、チーム固有状態、保存/再生/rulesetの移行契約と受入条件を別Issueへ分割する。
