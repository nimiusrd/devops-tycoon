# RI-186: 集中力を払うスプリント中の手札交換

対象: #582、親: #548。評価: **仮説を採用、操作UIと本番統合は保留**。

## 判断と最小試作

現行の `dealHand`、`playCardFromHand`、`applyAction`、`stepSprint` を利用する隔離モデル。手札の指定位置1枚を捨て札へ移し、山札先頭1枚で置換する。交換費用は集中力2、上限はスプリント当たり2回。山札枯渇時の再シャッフルはしない。山札順はseedで開始時に確定し、交換では乱数を消費しない。必要施策の確定ドローやカードの強化は行わない。

停止、完了、盤面枯渇後の下限tick待ち、上限到達、手札なし、山札なし、不正なインデックス・重複、集中力不足では、費用・カード・乱数・交換回数を変えない。発動済みカードは交換対象にならない。交換しただけでは組織基準値・効果を適用しない。引いたカードは既存の発動処理で一度だけ適用する。

交換前に全カード山が対象カードの完全かつ一意な分割であることを検証し、交換対象以外の重複・欠落・範囲外も拒否する。試作保存の任意項目 `sprintDeckIndices` で持ち込み対象を保持でき、未指定の既存JSONは全所持カードを対象とする。対象リスト自体の不正・重複も拒否する。

## 同じseed・資源での比較

seed `RI-186`。6枚のデッキ、手札3枚、初期集中力8。カードはレベル1の既存定義。定型16件を全件Coding中／Review待ちに置き、8tickの短い締め切りまで処理する。これは短時間の比較盤面であり、通常ランの尺・流入・WIP配置を再現したプレイテストではない。

共通入力は「先頭カードを0/1/2回交換→先頭1枚を発動→残集中力で毎tick割り込みレビューを試す」。引いたカードに合わせた最適化はしない。初期手札はレビューBot、自動テスト、PRサイズ制限。1回交換ではCopilot、2回ではドキュメント整備を引く。操作前にこの結果をプレイヤーへ保証しない。

## 採否と本番への境界

状況と現場介入の機会費用で交換の判断が変わる仮説を条件付き採用。費用2／上限2の本番採用は保留。通常流入・複数seed・自然発生する炎上を含む追加評価は次節に記録する。

通常ランから参照しないため、既存ゲーム値・保存形式・ruleset・UIを変更しない。試作専用 `version: 1` はカード各山・発動効果・組織・集中力・累積交換数・tick・PRNG消費位置をJSONで保持する。同じ交換順・発動・介入を保存再開後にも再現する。本番導入はDeckBarの交換選択と費用・上限・残山札の表示、RunEngine/worker入力、リプレイ記録、保存の検証・旧セーブの交換数0移行、ruleset更新を同一の統合単位に含める。WebGL未準備・システム停止・リプレイ閲覧での操作拒否も既存契約に合わせる。

## 通常流入の追加評価（2026-10-14）

`npm run prototype:ri186` で64 seedを同条件比較する。標準設定の28タスク・Coding枠6・完了下限77tickを使い、タスク種別と高価値率は既定分布からseedで生成する。全タスクを最初からCoding/Reviewに固定せず、通常どおりBacklogからWIPへ流入させる。各seedで交換0/1/2回を比較し、交換費用1/2/3の感度も記録する。

比較方針は「先頭の手札枠を指定回数交換し、そのカードを1枚だけ発動」。進行中は緊急な炎上があれば緊急対応し、それ以外ではReview待ちが4件以上なら割り込みレビューを試す。同seedでは交換以外の初期状態とこの介入方針を揃える。これは固定方針の比較で、プレイヤーが盤面を読んでカードや交換対象を選ぶ判断は再現しない。

交換なしの59 seedで自然発生の炎上があり、その条件でも1回交換の平均出荷は320.915から313.915へ下がり、平均残集中力は6.678から4.661へ下がった。2回交換では平均出荷315.881、平均緊急対応1.271回だった（交換なし1.254回）。全64 seedの全方針で28件すべてを完了し、時間切れはなかった。

**判断:** 固定方針で無条件に交換する場合、出荷平均は改善せず、集中力の余裕が減る。特に費用3で2回交換すると緊急対応回数も低下した。一方で出荷が増えたseedもあるため、状況を見て交換する仮説そのものは否定できない。費用2・上限2の本番採用と通常ラン統合は引き続き保留し、条件付き採用を維持する。

**次の作業:** 交換後の引きを見てから選ぶ不正な方針ではなく、手札・残山札の候補幅と現場の詰まりを使って「交換する価値がありそうか」をプレイヤーが判断できる説明を設計する。その判断基準を人間が評価した後に、本番実装Issueを切る。タスク完了数や時間切れに差が出なかった今回の固定方針比較は、本番の面白さや採用係数の証明として扱わない。

seedごとの比較値は [`hand-exchange-flow-comparison.json`](./hand-exchange-flow-comparison.json) に保存し、再生成スクリプトは [`scripts/ri186-hand-exchange-evaluation.mjs`](../../scripts/ri186-hand-exchange-evaluation.mjs)。
