## 行動効果（ノブ）

正本は `knobs.ts`。仮説を通すための後付け調整はしない。

今期の処理量は **育成前の能力** を使う。育成の `nextCapabilityAdd` は期末に入り、次期から効く。

| 行動 | processMul | 負荷軽減 | 危機軽減 | 消耗加算 | 次期能力 | 集中コスト |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 直接支援 | 1.6 | 20 | 24 | 7 | 0 | 1（枠を埋める） |
| 育成 | 0.72 | 3 | 2 | 2 | +14 | 0 |
| 委任 | 1.0 | 0 | 0 | 0 | 0 | 0 |

委任に「見ていない罰」や「委任した報酬」は無い。消耗は負荷+危機が能力を超えた分と、支援/育成の加算だけ。

## 公式

```
incoming = 10 + pressure * 0.32 + rngInt(-3, 3)
processed = capability * 0.4 * processMul
crisis' = clamp(crisis + incoming * 0.5 - processed * 0.3 - crisisRelief)
pressure' = clamp(pressure + incoming * 0.18 - processed * 0.14 - pressureRelief)
output = max(0, processed - crisis' * 0.18)
overload = max(0, pressure' + crisis' - capability)
fatigue' = clamp(fatigue * 0.82 + overload * 0.1 + fatigueAdd)
capability' = clamp(capability + nextCapabilityAdd)
会社成果 = sum(output) - 0.4 * sum(crisis') - 0.2 * sum(fatigue')
```

`clamp` は 0–100。表示は小数第 1 位。

会社成果は期間ごとに上式で出し、ラン合計は期間スコアの和。単一総合点で採否を決めないこと。H1–H4 はログの 短期出荷 / 消耗 / 未解決危機 / 次期能力 / 会社成果 / 判断回数 を別々に見る。

## 判断回数

前期にコミットした方針と今期の方針が異なれば +1。同じ方針の維持は 0。
初期方針は全委任。閲覧・チームカードの開閉は数えない。

## アームの走らせ方

UI のワンクリック、または `applyArm` → `runRemaining`。

1. **常時1チーム介入** — 毎期チーム A を直接支援、他は委任。安定・逼迫とも未変更。
2. **育成して委任** — 安定は従来どおり 1–2 期に 3 チーム育成、3 期以降は全委任。逼迫だけ後述の差分。
3. **全委任** — 毎期全チーム委任。未変更。
4. **状況で選ぶ** — 危機 ≥ 38 なら最も危機の大きい 1 チームを支援。安定の残り判定は従来どおり。逼迫だけ後述の差分。

### 逼迫シードだけの方針差分（before → after）

会社成果公式・安定シード・安定アーム・常時介入・全委任は変えていない。

| アーム | before | after |
| --- | --- | --- |
| 育成して委任 | 1–2 期は 3 チームとも育成。3 期以降は全委任 | 1–2 期は **シード初期のボトルネック（能力最小、同値なら危機最大。逼迫では B）だけ** 育成。途中で付け替えない。他は委任。3 期以降は全委任。育成期間 2 は据え置き |
| 状況で選ぶ | 支援以外は「能力 < 50 **かつ** 危機 < 38」なら育成 | 支援以外は能力 < 50 なら **危機が高くても** 育成。支援枠は最大 1 のまま |

逼迫初期のボトルネックはチーム B（能力 28 / 危機 62）。状況の初期方針は B 支援・A/C 育成。

ノブ: `KNOBS.crisis.trainThenDelegateOnlyBottleneck` / `KNOBS.crisis.situationTrainDespiteHighCrisis`。

手順:

1. `npm run dev` → `http://localhost:5174/?rd=intervene`（比較は既定 8 期）
2. 逼迫または安定を選ぶ。期間を 6 にする場合は UI か `?periods=6`
3. アームを押し、「この方針で残り期間を一括実行」
4. 期間ログを見る。`JSON をコピー` または `TSV を保存`
5. 同じシード・同じ期間数で次のアームを繰り返す（2 × 4 × 8 期）

手動でチーム方針を変えて 1 期ずつ進めてもよい。状況アームは期が進むと次期の提案を更新する。

## 仮説（通すためにバランスしない）

- H1 状況選択は、常時介入 / 全委任より会社成果が良く、消耗・危機を悪化させない
- H2 育成→委任は常時介入より短期出荷で遅れ、能力と会社成果で追いつく
- H3 全委任は逼迫で負け、安定では許容
- H4 判断回数が多いほど良い、ではない
