# RI-218: 共有専門家の支援枠を3件の依頼へ配る

対象 #614 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と配分契約

通常ランから隔離した純TS試作。依頼の担当チームは RI-216 の platform / product / incident を使う。専門家の雇用や異動は作らない。seed `RI-218` は盤面識別子で乱数は使わない。専門家は1人で、1期間に使える枠は1。各依頼の必要枠は2。同じ期間に複数の依頼へは配置できず、専門家の所在は常に1チームだけになる。

依頼は3件。期限の出荷、未解決リスクの確認、設計相談。完了 tick が期限以下なら定義した価値を得る。期限を過ぎて完了した場合は価値0だが、その依頼の未解決リスクは残さない。未完了は `pending` のままで、期末にもリスクとして残る。放置しても全社敗北にはしない。閲覧は進捗もリスクも変えない。

`due` は出荷の期限が近く、設計相談の未解決リスクは5。`exposure` は確認のリスクが14で、出荷の期限は tick 1。どちらも期末4。

## 同条件比較

| 盤面 | 期限が早い依頼から | 未解決リスクが大きい依頼から |
| --- | ---: | ---: |
| 期限が近い | 8 | 4 |
| リスクが大きい | 4 | 7 |

差引は得た価値−未完了依頼の未解決リスク。`due` では出荷を tick 1 に終えてから確認を終える差引8が、設計相談を先にした4を上回る。設計相談は pending のままリスク5が残る。`exposure` では確認を期限内に終えてから設計相談を終える差引7が、出荷を先にして確認が期限超過になる4を上回る。期限超過の確認は価値0で、出荷は pending のリスク1が残る。

固定枠の仮説比較であり、本番の面白さや一般的優位の証明ではない。次は必要枠、期限、未解決リスクの感度と、依存でブロックされた依頼を見る。
