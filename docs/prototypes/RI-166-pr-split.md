# RI-166: 本当に分かれるPR

対象 #562 / 親 #548。結論: **部分出荷の仮説を限定採用、本番統合は保留**。人間のプレイ評価は未実施。

## 固定盤面とルール

通常ランから隔離した純TS試作。seed `RI-166` は盤面識別子であり乱数は使用しない。1担当・初期集中力6、親の総仕事6・投入済み2・残り4、総価値12。期末3/10tickの各盤面で単一PRと分割を比較。集中力1と価値1を等価とする差引指標は暫定であり、本番評価式ではない。

分割は集中力2を払い、親を履歴として残して子2件（各仕事3/価値4）と統合1件（仕事2/価値4）を生成する。投入済み仕事は巻き戻して廃棄し、追加の総仕事は8。操作自体はtickを進めず、作業は1tickで1工数。親の価値は退役後に加算しない。単一PRの完成条件は残工数0、分割の全完成は子2件＋統合のDone。子1件だけでも価値4を出荷できる。

親子IDと統合依存を保存。採番は単調増加し既存IDを回避。退役・Done・子の再分割、資源不足、未知ID、期末は無消費で拒否。未完成の子がある統合作業も拒否。親を分割後に作業して価値を二重取りできない。

統合失敗の比較盤面では初回統合だけ2工数の再確認が必要。統合価値4を保留するが出荷済み子の価値8は維持し、再確認完了時に総価値12になる。失敗有無は開始前に公開する固定条件で、実事故抽選は再現しない。未完成仕事は期末残工数として記録する。

短期では小さな先行成果を確保できるが、余裕があると分割の工数と集中力を避ける方が有利。統合失敗はtick8時点の価値8を維持し、tick10で価値12。`pr-split-comparison.json` に同じ初期状態、入力列、成果、代償と残工数を記録。全比較の再生成と毎入力JSON保存再開をテストする。

次は部分機能の独立性、統合失敗時の子側の障害、複数担当、期末の繰越、分割時期と集中力の機会費用を比較する。本試作では子の価値を独立利用できる前提が強く、製品モデルとしての採用には追加評価が必要。
