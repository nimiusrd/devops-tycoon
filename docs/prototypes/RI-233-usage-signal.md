# RI-233: 観測した利用で、追加投資と撤退を比べる

対象 #629 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。優劣が反転する位置は要因比較に記録した。人間のプレイ評価は未実施。本番採用の結論は出さない。

## 固定盤面と利用

通常ランから隔離した純TS試作。seed `RI-233` は盤面識別子で乱数は使わない。余力は4。反応する人数は RI-229 の固定ロスター4人で、期間中に増えない。機能は api、screen、billing の3つで、各機能の完成作業は5、出荷量は15である。3つの観測で出荷量と予測は同じで、予測は各機能3。期間は4。利用0の機能を閉じると保守枠8が一度戻る。利用1以上の機能を直すと、その利用に1を足した値が一度入る。実際の利用は人数以下である。敗北状態にはしない。

閲覧は実際の利用を出さない。操作前に示すのは、出荷量、予測、撤退値8、改善の上乗せ1、余力、人数である。出荷は機能を公開するだけで、利用も価値も付かない。利用は観測したとき一度だけ見え、二度目の出荷、二度目の観測、同じ機能の再改善は状態を変えない。観測前の改善は拒否する。

予測のまま投資する手順は、出荷のあと予測の同点を api とみなし、残りの各期間でその機能の実際の利用を得る。観測はしない。追加投資は、出荷してから観測し、見えた最大利用へ残りの期間を入れる。改善撤退は、出荷してから観測し、見えた最小利用を一度だけ直し、次の期間に公開済みの値を一度得る。同点は api、screen、billing の順で先にある機能を選ぶ。

## 同条件比較

行の中だけを比べる。出荷量はどの行も15である。

| 観測 | 実際の利用（api, screen, billing） | 予測のまま | 観測して追加 | 観測して改善 |
| --- | --- | ---: | ---: | ---: |
| 予測の先頭が伸びる | 4, 1, 1 | 12 | 8 | 2 |
| 予測の先頭が外れ、別機能が伸びる | 1, 2, 4 | 3 | 8 | 2 |
| 一つが使われず、残りは分かれる | 1, 3, 0 | 3 | 6 | 8 |

予測の先頭が当たる観測では、観測に使う1期間のため、予測のまま12が追加8と改善2を上回る。改善の対象は screen で、得られるのは2である。予測の先頭が外れる観測では、観測して billing へ追加する8が、予測のまま3と api の改善2を上回る。利用0がある観測では、billing を閉じる8が、screen への追加6と予測のまま3を上回る。

同じ出荷量でも、見えた利用が一つに偏るか、予測と違う機能が伸びるか、使われない機能があるかで、次に選ぶ手が変わる。固定3観測の仮説比較であり、本番の利用計測の証明ではない。撤退値、観測に使う期間、予測の偏りの感度は次節。初回の3観測表はそこでは再計算しない。

## 要因を一つずつ動かした比較

固定戦略の計算である。人間のプレイ評価はしていない。固定手順の得点を、本番の利用計測や、プレイヤーが境界を見て選べることの証明にはしない。本番採用の結論は出さない。

資源は初回と同じ。seed `RI-233`、余力4、人数4、出荷量15、期間4、機能は api、screen、billing。改善の上乗せは1。実際の利用は動かさない。利用が一つに偏る盤面は api 4、screen 1、billing 1。予測と違う機能が伸びる盤面は api 1、screen 2、billing 4。使われない機能がある盤面は api 1、screen 3、billing 0。基準は撤退値8、観測1期間、予測の偏り0（各機能3）。動かした要因以外は変えない。数値は本番定数ではない。

比べるのは追加と撤退である。追加は出荷して観測し、見えた最大利用へ残期間を入れる。得点は残期間×最大利用。撤退は出荷して観測し、見えた最小利用を一度直し、次の期間に一度回収する。利用0の回収は撤退値、利用1以上の回収は利用+1で、どちらも一度だけ。予測のままは併記する。予測のままが最大でも、追加と撤退の向きは別である。同点は優劣が無い。同点のとき先に選ぶ機能は初回と同じで、api、screen、billing の順。

残期間は、期間4から出荷1と観測期間を引いた値である。0未満にはしない。観測期間が2以上だと、改善のあと回収が期間内に残らず、撤退の得点は0になる。観測期間0では回収のあと1期間余る。その期間は `hold` で進め、得点は足さない。初回の観測1期間では `hold` は出ない。予測は人数を超えてよい。実際の利用は盤面の値で、人数以下である。

撤退値だけを動かす。観測は1期間。予測の偏りは0。利用が偏る盤面と、予測と違う機能が伸びる盤面は、撤退値0から12まで追加8、撤退2のまま。どちらの最小利用も1以上なので、改善は撤退値を使わない。反転しない。予測のままは、偏る盤面が12、外れる盤面が3。

使われない機能がある盤面だけ、撤退値が回収に入る。追加は screen の利用3を2期間で6。撤退は billing を閉じた値。

| 撤退値 | 予測のまま | 追加 | 撤退 | 追加と撤退 |
| ---: | ---: | ---: | ---: | --- |
| 0 | 3 | 6 | 0 | 追加 |
| 5 | 3 | 6 | 5 | 追加 |
| 6 | 3 | 6 | 6 | 同点 |
| 7 | 3 | 6 | 7 | 撤退 |
| 8 | 3 | 6 | 8 | 撤退 |
| 12 | 3 | 6 | 12 | 撤退 |

撤退値8は初回と一致する。追加が上回るのは5まで。6で同点になり、7で撤退へ反転する。12でも撤退が上のまま。

観測に使う期間だけを動かす。撤退値は8。予測の偏りは0。予測のままは観測しないので、この軸では得点が変わらない。

利用が一つに偏る盤面。撤退の対象は screen で、回収は2。

| 観測期間 | 予測のまま | 追加 | 撤退 | 追加と撤退 |
| ---: | ---: | ---: | ---: | --- |
| 0 | 12 | 12 | 2 | 追加 |
| 1 | 12 | 8 | 2 | 追加 |
| 2 | 12 | 4 | 0 | 追加 |
| 3 | 12 | 0 | 0 | 同点 |

観測1は初回と一致する。撤退が追加を上回る期間はない。2と3のあいだで同点になる。

予測と違う機能が伸びる盤面。追加の対象は billing の利用4。撤退の対象は api で、回収は2。

| 観測期間 | 予測のまま | 追加 | 撤退 | 追加と撤退 |
| ---: | ---: | ---: | ---: | --- |
| 0 | 3 | 12 | 2 | 追加 |
| 1 | 3 | 8 | 2 | 追加 |
| 2 | 3 | 4 | 0 | 追加 |
| 3 | 3 | 0 | 0 | 同点 |

観測1は初回と一致する。こちらも撤退側へは反転しない。2と3のあいだで同点になる。

使われない機能がある盤面。追加は screen の利用3。撤退は billing の0で、回収できるときは8。

| 観測期間 | 予測のまま | 追加 | 撤退 | 追加と撤退 |
| ---: | ---: | ---: | ---: | --- |
| 0 | 3 | 9 | 8 | 追加 |
| 1 | 3 | 6 | 8 | 撤退 |
| 2 | 3 | 3 | 0 | 追加 |
| 3 | 3 | 0 | 0 | 同点 |

観測0では追加9が撤退8を上回る。観測1で撤退へ反転し、初回と一致する。観測2では回収が残らず撤退0になり、追加3が上へ戻る。観測3で同点になる。

予測の偏りだけを動かす。撤退値は8。観測は1期間。api は 3+偏り、billing は 3−偏り、screen は 3 のまま。0未満の予測は0。追加と撤退は観測した実際の利用で対象と得点が決まる。偏り -2 から 2 まで、追加と撤退の得点は変わらない。反転しない。予測のままだけが、予測の最大にある機能の実際の利用を3期間足す。偏り -1 以下は最大が billing。0以上は api。

| 盤面 | 偏り -1 以下の予測のまま | 偏り 0 以上の予測のまま | 追加 | 撤退 | 追加と撤退 |
| --- | ---: | ---: | ---: | ---: | --- |
| 利用が一つに偏る | 3 | 12 | 8 | 2 | 追加 |
| 予測と違う機能が伸びる | 12 | 3 | 8 | 2 | 追加 |
| 使われない機能がある | 0 | 3 | 6 | 8 | 撤退 |

偏り0は初回と一致する。予測と違う機能が伸びる盤面では、偏り -1 以下の予測のまま12が追加8より大きい。比べている追加と撤退は、追加のままである。

`usage-signal-factor-comparison.json` に条件、規則、初期状態、入力列、得点、優劣、反転を残す。対象テストが再計算し、撤退値8・観測1期間・偏り0の行が初回JSONの予測のまま・追加・撤退と一致することを照合する。初回の比較JSONは更新していない。

次に解く不確実性: 予測の偏りを -1 以下にすると、予測と違う機能が伸びる盤面では観測しない追加が12で観測後の撤退2を上回るが、使われない機能の盤面では観測しない追加が0になり撤退8を下回る。この偏りを見て観測するかを選ぶ適応は未検証。

この要因比較は本番採用の判断を変えない。仮説は限定比較の採用のまま、本番統合は保留。

## 本番境界と検証

製品の販売、勝敗、画面更新による利用の引き直しへは接続しない。閲覧順で結果は変わらない。通常の編成、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。本番採用時は出荷済みと利用観測の保存、閲覧から実際の利用を除く契約、完成と利用の分離を別Issueに分割する。version 1の信頼済み内部JSONには再現のため実際の利用を含める。外部入力検証と通常保存互換は対象外。

`usage-signal-comparison.json` に観測、初期状態と入力列、得点を記録した。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。要因比較は Node 24 で対象ユニット、保存再開と入力再生、lint、format:check。UI/Pixiの変更はなく、E2Eとgalleryは対象外。通常ランの本番、UI、保存、rulesetへは接続していない。customerInterview と demandProbe は変更していない。
