# RI-213 人物の経歴

対象 [#609](https://github.com/nimiusrd/devops-tycoon/issues/609)。親 #548、関連 #537・#681。

## 初手の判断

現在ランの経歴データを限定採用する。編成で同じ人物を確認し、初昇格や休職・復帰を今後の配置・育成を考える材料にできるかを検証するための土台とする。節目は実際に生じた成長や状態変化から記録する。プレイヤーの選択、費用、係数、収支、勝敗のルールは現行どおり。

#681で使うスプリント結果の昇格記録から、人物ID・当時の名前・昇格先を取得する。休職は成長時のスタミナ枯渇と四半期レビューでの組織再編が対象。復帰はスタミナ回復で休職が解けた場合で、スプリント間回復、休息、訪問済みの非選択チームも対象とする。編成の復帰通知は同じ人物につきラン内で一度だが、経歴には実際に起きた各回の復帰を記録する。

## 記録と保存の境界

- 人物IDはチーム内で採番される。チームIDと人物IDで照合し、同じ名前や別チームの同じ人物IDを区別する。当時の名前、昇格先、休職理由は記録に保持する。
- 新規ランでは完了スプリント数0から記録する。履歴のない互換セーブでは、再開時点の完了スプリント数を開始点として、そこから初めて確認した昇格と休職・復帰を記録する。すでに昇格したか不明な人について、旧データに残る能力やランクから履歴を補わない。履歴を持たないリプレイのキーフレームには開始点も補わない。
- 休職と復帰の番号には、発生時点の完了スプリント数を使う。通常スプリントでは新たな休職者を終了時回復から除外し、その後の休息で復帰しても次の休職は次スプリント以降。四半期末には終了時回復で復帰した人物が再編で休職しうるため、両方をその番号で起きた順に記録する。再編後は次四半期の編成へ直行するため、それ以前に同じ番号で同一人物が同種の状態変化を繰り返す経路はない。
- 途中セーブ、リプレイ、反実仮想には既存のフェーズ境界のスナップショットで保持する。リプレイの各場面は収録時点の経歴を表示用データとして復元する。保存とリプレイのスキーマ番号、バランスルールセットは変更しない。ランを新しく開始すると履歴は空に戻る。

## 固定条件での検証

`tests/unit/sim/memberHistory.test.ts` で、seed `ri213-member-history`、easy、初期資源と現行係数を固定する。必要なロスター・休息・四半期レビューの状態をスナップショットに用意し、昇格・休職・回復・再編処理そのものをエンジンの公開操作で実行する。

## 次の判断条件

人物の経歴を読む画面、ボス突破の記録、人物への愛着や編成判断に役立つかの人間によるプレイ評価は次の検討対象とする。編成に短い履歴への入口を設けた試作を用意し、同じseed・資源・入力列で既存の編成画面と比較する。休職・復帰や初昇格の当時の経緯を説明できるか、次の配置を決める助けになるか、編成操作を妨げず見つけられるかを確認して、画面の採否と続けて記録する出来事を判断する。

## 編成での経歴表示

記録があるメンバーカードに「経歴」を追加する。必要なときに開いて前回の休職や復帰を確認し、配置や休養を考えられるようにする。レリックや進化をまとめる会社プロフィール、直近スプリントの昇格を伝える一言と併用できる。

- 支援中チームのIDとメンバーIDを照合し、当時の名前、通算スプリント番号、初昇格先、休職理由、復帰を収録順で表示する。同じ番号に複数イベントがあっても順序を保つ。
- 途中再開から記録した旧セーブでは、記録を始めた完了スプリント数を編成に一度表示する。記録がなければ、現在のランクや休職状態から節目を補わない。
- 既存の折りたたみを使用し、初期状態は閉じる。編成ダイアログで配置がロックされていても閲覧できる。リプレイのセットアップでは収録フレームの情報を読み、配置操作は無効のままにする。

固定比較は Easy の seed `ri213-formation-history` を使用する。初期予算、配置、ロスター、ラン進行を共通にし、公開 GameHandle の保存書き出し・取り込みで表示対象の経歴と記録開始を準備する。閉じた状態と開いた状態を同じ保存から比較し、開閉後も予算、ロスター、フェーズ、完了スプリント数、経歴が一致することを確認する。同名、別チームの同じID、現在と異なる名前・階級、同一スプリントの復帰と休職を含む。旧セーブと収録キーフレームは別の入力で確認する。配置と開始は通常UIから操作し、実WebGLのスプリントで再度経歴を開けることを確認する。

記録を読む導線を限定採用する。機械検証で分かるのは記録と表示の一致や操作の両立までで、編成判断や人物への愛着への効果は人による比較プレイが残る。同じ条件で経歴を開く場合と開かない場合を比較し、次の配置・休養の理由を説明しやすくなるかを確認する。その結果を、経歴の位置や新たに記録する節目を判断する材料にする。
