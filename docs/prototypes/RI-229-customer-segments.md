# RI-229: 同じ製品出荷を、新機能層と安定層で比べる

対象 #625 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と顧客層

通常ランから隔離した純TS試作。seed `RI-229` は盤面識別子で乱数は使わない。製品の機能完成、余力4、必要量5、事故は RI-228 の障害対応が要る盤面を使う。顧客は新機能層と安定層で、合計はどちらも4人。新機能が多い構成は3人と1人、安定が多い構成は1人と3人。人数は期間中に増えない。敗北状態にはしない。

新機能層は、その期間に完成した機能1つにつき10。機能への割当が0の期間は-3で、これが許容できない失敗。判定は受理された作業量ではなく、入力で機能へ割り当てた合計で行う。未完了の進捗は0。安定層は運用へ1以上を置いた期間が2、事故が出た期間が-4で、事故が許容できない失敗。完成済み機能へ再度割り当てても新機能層の完成点は増えず、未投入の失敗にもしない。

集中、分散、運用枠の投入列は RI-228 と同じ。顧客構成だけを変える。

## 同条件比較

差引は新機能層の満足＋安定層の満足。

| 顧客構成 | 集中 | 分散 | 運用枠 |
| --- | ---: | ---: | ---: |
| 新機能が多い | 48 | 18 | 36 |
| 安定が多い | -16 | -26 | 28 |

集中の投入、機能への投入12、完成 api と screen は両構成で同じ。差引は新機能が多い48、安定が多い-16。新機能が多い構成では集中の48が運用枠36と分散18を上回る。安定が多い構成では運用枠の28が集中-16と分散-26を上回る。一方の層だけを満足させる方針が、もう一方の構成では上回らない。

固定4人の仮説比較であり、本番の面白さや一般的優位の証明ではない。次は完成点数、事故の不満、人数比の感度を見る。

## 本番境界と検証

現行のステークホルダー信頼、勝利種別、顧客数の増加へは接続しない。閲覧順で結果は変わらない。通常の編成、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。本番採用時は顧客構成の保存、完成と事故の満足を分けて記録する契約、勝利判定への非接続を別Issueに分割する。version 1の信頼済み内部JSONのみ。外部入力検証と通常保存互換は対象外。
