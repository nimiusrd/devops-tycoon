# RI-264: 固定危機盤面の救済パズル試作

対象: #660 / 親: #548。評価結論: **修正した盤面を追加評価へ進める**。プレイヤー用モードとしての本番採用は保留。

## 盤面・制限・救済条件

`src/prototypes/rescue.ts` の `createRescuePrototype` が課題 `review-crisis-1` を新規生成する。seedは `RI-264-review-crisis-1`、20件のタスクのうち先頭6件がAI支援のcomplexレビュー待ち、次の2件が炎上中で猶予50/70tick、残り12件がバックログ。レビュー余力60・士気40・AIリテラシー25・テスト30・品質40から始める。

120tickの時間制限、集中力9、成功介入最大3回。既存の割り込みレビュー・アンドン・緊急対応だけを使う。効果・費用・CD・乱数・スプリント進行は本番の `applyAction` / `stepSprint` を再利用し、別の簡略効果を作らない。入力をtick開始時に適用し、その後1tick進める。失敗入力も理由付きで記録するが成功回数・集中力は消費しない。

救済は終了時の出荷180以上、延焼2以下、レビュー余力10以上、炎上0件の全条件。全タスク完了を要求せず、鎮火しつつ回る会社へ戻す目標とする。通常の勝利判定とは独立している。締切時の未処理を本番の時間切れ処理で消して成功扱いにしないため、内部の安全上限は121tickに設定し、120tickの課題期限で盤面をそのまま残す。

## 開始猶予・難易度調整

初期HP28では比較した全方針が余力条件を満たさず、鎮火→レビュー→鎮火でもHP1.9。40でも同方針はHP1.9だったため、初期HP60へ調整した。救済条件を緩めて成功にせず、判断に使える初期余力を増やした。無介入でも最初の10tickは終了せず、課題の最終評価まで即敗北を出さない。通常ランのF-5原則を変更するものではない。

現状は成功経路と複数の失敗・機会費用を確認できたので追加評価へ進める。数分の遊びや暗記に留まらないかは人間のプレイ確認が必要。次は介入時刻を広げた比較、初期キューが厚い条件、火の猶予、説明の理解度、複数の成功経路を評価する。

## 保存・通常ラン・報酬の境界

状態は `kind: rescue-prototype` / `challengeId` / `version: 1` で通常のRunSaveと区別する。途中のJSON保存には乱数の内部状態と入力履歴を含め、再開後も同じ結果になる。本番保存の読み込みや `RunEngine` の通常再開へ渡さない。課題の新規開始と試作中の再開は別の操作として扱う。

本番モード・UI・SPEC・固定トラック・勝利種別・通常メタ報酬は未変更。試作からXP・解放・実績等を付与する経路はない。通常ランへ統合する場合は別Issueでタイトルからの入口、保存識別・ruleset、停止契約、報酬、期限表示を定義する。#536の介入表示改善も完了扱いにしない。
