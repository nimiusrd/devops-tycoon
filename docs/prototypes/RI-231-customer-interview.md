# RI-231: 短納期と不確実な要望で、即着手と聞き取りを比べる

対象 #627 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と聞き取り

通常ランから隔離した純TS試作。seed `RI-231` は盤面識別子で乱数は使わない。余力は RI-228 の4。依頼者は RI-229 の固定ロスターで、短納期は新機能が多い3対1、不確実は安定が多い1対3。機能は api、screen、billing。必要量は4なので、1期間で1機能が完成する。正しい機能の完成価値は12で一度だけ。期限後の完成は10を引く。敗北状態にはしない。自由会話や外部モデルは使わない。

聞き取り前の閲覧は、噂の api と不明な需要だけを示す。真の需要は閲覧に出さない。聞き取りは1期間の余力4を使い、有力候補と未確認の billing を返す。二度目の聞き取りは状態を変えない。未確認の候補が残るので、聞き取りは正解の公開ではない。

短納期の真の需要は api で、期限は最初の1期間。不確実な盤面の真の需要は screen で、期限は3期間。即着手は噂の api を作る。聞き取りは確認してから有力候補を作る。別機能は確認してから billing を作る。

## 同条件比較

差引は完成価値−期限遅れ。聞き取り費用は失った期間として結果に残り、差引からは二重に引かない。

| 盤面 | 即着手 | 聞き取り | 聞き取り後に別機能 |
| --- | ---: | ---: | ---: |
| 短納期 | 12 | 2 | 0 |
| 要望が不確実 | 0 | 12 | 0 |

短納期では即着手の12が、聞き取り2と別機能0を上回る。噂が正しく、確認に期間を使うと完成が期限を外す。要望が不確実な盤面では聞き取りの12が、即着手0と別機能0を上回る。即着手は方向違いの機能を完成させ、別機能は聞き取り後でも報酬がない。

固定2盤面の仮説比較であり、本番の面白さや一般的優位の証明ではない。次は期限、確認費用、未確認候補の数の感度を見る。

## 本番境界と検証

顧客の自由会話、ネットワーク、外部の言語モデル、勝敗へは接続しない。閲覧順で結果は変わらない。通常の編成、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。本番採用時は聞き取り済みの保存、閲覧から真の需要を除く契約、期限遅れと確認費用の分離を別Issueに分割する。version 1の信頼済み内部JSONには再現のため真の需要を含める。外部入力検証と通常保存互換は対象外。

`customer-interview-comparison.json` に初期状態、入力列、完成価値、期限遅れ、確認費用、差引を記録した。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
