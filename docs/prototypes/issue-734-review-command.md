# #734 レビュー工程を起点にする介入

判定は**再試作**。工程から介入の候補に到達し、作用先・効果・代償を確認して実行するところまで実 WebGL のスプリントにつないだ。次は、同じスプリント状態で固定の介入バーと操作を比較し、探索の速さと誤発動、効果と代償の理解を人間のプレイで確かめる。

## 試し方

起動 URL に `?rd=review-command&seed=ri141-review-pressure-0&tutorial=off` を付け、難易度ハード・試練なしで開始する。開発フローのレビュー工程を選ぶと、盤面直下に割り込みレビュー・ペアレビュー・流入停止（アンドン）が出る。介入を選ぶと作用先・効果・代償と現在の可否が表示され、「実行する」で発動する。「取消」か Escape で選択を破棄できる。比較する固定介入バーは同じ URL でも使用できる。

- 割り込みレビューはレビュー待ちの先頭をまとめて処理する。レビュー処理と追加のシニア HP を消費する。
- ペアレビューは先頭の PR 処理と AI 習熟を両立する。待ちなしでは処理 0 件の既存ルールを表示する。
- アンドンは待機から実装への流入を一時停止する。薄いレビューキューでは士気・シニア HP の負担が増える。

介入を選んだ後に見込み処理件数またはアンドンの追加負担が変わると、確定ボタンが「変更を確認」に変わる。一度押して現在の条件を確認し、次に「実行する」を押す。工程全体が対象なので、見込み処理件数と代償が等しければその時点の先頭から処理する。発動時の効果は既存 dispatch の結果から盤面と出来事欄へ返す。

## 同一 seed の比較条件

難易度ハード・試練なし・seed `ri141-review-pressure-0` の初期スプリントを、Playwright で公開操作から再現する。同じ場面・同じ介入なら、固定ボタンは 1 操作、工程からは 3 操作（工程→介入→確定）。効果や代償が変わった場合は確認が 1 操作増える。

| 場面 | 入力と確認 |
| --- | --- |
| 平常 | tick 0 のレビュー待ち 0 件、集中力 13、シニア HP 95、士気 60。割り込みは「レビュー待ちなし」で無効、ペアは 0 件を明示。工程と介入を選び、Esc で取り消して介入回数・集中力消費が変わらないことを確認する。 |
| 渋滞 | 公開の `step(100)` でレビュー待ち 8〜11 件まで進める。アンドンは渋滞判定の下限 10 件に達するフレームを使う。薄い状態で選択したアンドンは代償を再確認してから一度だけ実行し、士気消費と流入停止、再使用待ちを確認した。tick 12 の割り込みレビューでは固定ボタンと工程起点の両方で 4 件を処理し、レビュー待ち 8 → 4 件、集中力 13 → 10、シニア HP 89 → 80.6、士気 64 → 65 だった。タッチでも確定後に盤面と出来事欄を確認した。 |
| 炎上 | レビュー待ち 12 件以上に達してから、進行中の炎上が出るまで進める。どちらの導線でも tick 20 のレビュー待ち 12 件、炎上 1 件、集中力 13、シニア HP 84.15、士気 66 を再現した。レビュー工程から割り込みの確認欄を開き、警告・盤面・取消ボタンへの到達を 320×568、390×844、768×1024、1024×768、1440×900 で確認する。 |

人間による探索時間、誤操作率、効果や代償の理解は未計測。次回は各場面の同一フレームから、固定介入バーと工程起点の順序を入れ替えてプレイする。指示提示から介入を決めるまでの時間、意図外の発動数、実行前に説明できた作用先・主要な代償を記録する。探索時間と理解が改善し、誤発動が増えない場合に本番統合の範囲を判断する。

工程の起点は既存 HTML 工程要約のセル全体を使う。狭幅の工程セルは DS-08 の 24 CSS px の基準を満たす高さとし、盤面の警告やドラッグ対象へ重ねず到達できる範囲に留めた。確認欄の操作は高さ 44 CSS px。フォーカスと作用先は枠・文言でも示し、通常設定と reduced motion で同じ表示・操作を使う。
