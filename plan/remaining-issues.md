### RI-78 スプリント間投資のうち、ショップと休息の選択が結果を変えない — 完了

### RI-93 子コンテンツの変更で再崩壊する画面レイアウト構造

**高優先度の技術基盤エピック。** RI-69 / RI-70 で確認済みの重なりと狭幅操作性は解消しているが、
スプリント画面全体は `Hud`・`RunBar`・盤面・手札・介入バーを `.app` 直下の1本の Flex 列へ並べ、
盤面を他要素が使った残り高さへ収めている。警告文、効果タグ、担当選択などの内容量が増えるたび、
`src/styles.css` 冒頭の `app-sprint-layout` へ `overflow`・固定値・メディアクエリを追加して補正しており、
変更が別の viewport / 表示状態で盤面縮小・重なり・情報欠落を再発させる。

根本原因は次の4点である。

- 画面全体の配置責務を持つレイアウトコンポーネントが無く、子コンポーネントの内容量が盤面寸法を直接変える。
- 全画面のスタイルが6,000行超の `src/styles.css` に集中し、離れたセレクタとソース順による上書きが暗黙の契約になっている。
- 860pxブレークポイント、DOM/Pixiの寸法・配色などが CSS / React / Pixi 間で手動同期されている。
- 通常CIのレイアウト契約は 1440×900 と 390×844 の初期スプリントに限られ、長文・警告・最大アイテム数・武装状態・短い画面などの組合せを検知しない。Pixi視覚回帰も既定CIではスキップされる。

受入条件:

- `SprintLayout` 相当の画面レイアウト所有者を設け、HUD・ステータス・盤面・操作領域を名前付きスロットとして配置する。通常高さでは盤面専用領域を確保し、収まらない高さでは明示的なスクロール構成へ切り替える。
- DOM/Pixi共通の `AspectStage` 相当へアスペクト比・contain・ResizeObserver責務を集約し、即時親要素を暗黙に参照して幅だけを書き換える構造を廃止する。
- 画面／コンポーネント単位のスタイル境界（CSS Modules または同等のスコープ）とレイアウトプリミティブを導入し、`.app.app-sprint-layout .子要素` の横断上書きやファイル末尾のソース順依存を解消する。
- ブレークポイント、盤面設計寸法、DOM/Pixi間で共有する主要寸法・色の正本を一元化し、「styles.css と同値」という手動同期を残さない。
- 320×568、390×844、768×1024、1024×768、1440×900 以上の代表 viewport と、HUD展開、最長警告、最大レリック、長い効果タグ、担当選択、結果オーバーレイを組み合わせたレイアウト契約E2Eを通常CIで実行する。
- 契約E2Eで横スクロール無し、主要領域の非交差、盤面比率・最低寸法、操作バー到達性を検証し、DOM/Pixi双方の合成画面を少数の視覚回帰で固定する。
- 既存のRI-69 / RI-70 E2E、通常E2E、`npm run lint`、`npm run format:check` が成功する。

分割順:

1. [RI-94](#ri-94-レイアウト契約e2eの状態fixtureとviewportマトリクス) で現状を契約テストとして固定する。
2. [RI-95](#ri-95-スプリント画面シェルの名前付きスロット化) で画面全体の配置責務を独立させる。
3. [RI-96](#ri-96-スプリント盤面の共通aspectstage化) で盤面のサイズ計算責務を独立させる。
4. [RI-97](#ri-97-スプリントレイアウトcssの専用境界への隔離) でカスケードの結合を外した後、[RI-98](#ri-98-レスポンシブ表示モードの正本一元化) でブレークポイントの正本を移す。

6. [RI-100](#ri-100-共通aspectstageの全社部署業界画面への展開) で他の盤面系画面へ実績のある構造を展開する。

親エピックの難易度は**高**だが、子課題はそれぞれ1PRで完了できる範囲に限定する。RI-94〜96を
