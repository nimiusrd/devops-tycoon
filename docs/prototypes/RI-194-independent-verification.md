# RI-194: 実装と検証の独立性

対象 #590 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と操作

通常ランから隔離した純TS試作。seed `RI-194` は盤面識別子（乱数なし）。実装手法は `script` で3tick。検証手法は `script` か `walkthrough`。同じ手法の検証は1tick、別手法は3tick。独立性はラベルではなく、検証手法が実装手法と違うこと。違うときだけ共通見落とし `assumption` を見つける。`load` はどちらでも残る。

手法の設定はtickを消費せず、最初の作業の前だけ変更できる。未知の手法、同じ手法の再設定、着手後の変更、手法なしの進行、期末は無消費で拒否する。実装が終わってから検証し、検証の最後のtickで一度だけ出荷する。出荷価値は12から、見逃した `assumption` と `load` を引く。期末までに検証が終わらなければ未出荷で0。

比較方針は公開情報だけを使う。`same` は `script` で検証する。`independent` は `walkthrough` で検証する。

## 同条件比較

| 盤面 | 同じ手法 | 別手法 |
| --- | ---: | ---: |
| 低影響、期末5（見落とし4） | 8 | 0 |
| 高影響、期末8（見落とし14） | -2 | 12 |
| 高影響に負荷5、期末8 | -7 | 7 |

差引=出荷価値。未出荷は0。単位を等価とする暫定指標。

低影響で期末が短いときは、同じ手法が4tickで8を出荷する。別手法は6tick必要で期末5では未出荷の0。追加検証が間に合わない。

高影響では、同じ手法の-2より別手法の12が上になる。見落としの大きさで、確認時間を払う価値が入れ替わる。

負荷つきでは別手法が `assumption` を見つけても `load` の5は残る。出荷は7。同じ手法は両方見逃して-7。独立検証は共通見落としにだけ効き、すべての危険は消さない。

## 本番境界と検証

案10のレビュー深度は確認に使う時間の量。本件は確認方法が実装と同じかどうか。現行の品質・テスト指標だけではこの違いを表さないため、通常ランへは接続しない。通常の保存、ruleset、勝敗、SPEC、固定トラック、WebGL停止契約へ接続しない。本番採用時は手法の表示、保存、入力再生を別Issueで設計する。version 1の信頼済み内部JSONのみ。外部入力検証と通常保存互換は対象外。

対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
