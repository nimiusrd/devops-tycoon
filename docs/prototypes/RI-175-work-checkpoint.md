# RI-175: 作業途中のチェックポイント

対象 #571 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と操作

通常ランから隔離した純TS試作。seed `RI-175` は盤面識別子（乱数なし）。期末8、Coding枠1、集中力4。機能仕事は工数6・期限内価値22・期限7、期限後完成は価値4。開始進捗4を完了間近、開始進捗1を初期段階とする。緊急仕事は工数2・価値14・期限3、期限内に完成しなければ代償6を一度だけ課す。未完了の機能価値は成果に足さない。

時間を進める操作は `work` / `checkpoint` / `resume` / `reset` / `restart` / `wait`。`start` は空き枠へbacklogを進捗0で置くだけで時間を進めない。`checkpoint` は着手中かつ進捗が1以上かつ未完了の仕事を `saved` にし、進捗を変えず枠を空け、集中力1を払う。`resume` は保存進捗のままCodingへ戻し、そのtickは進捗を増やさず集中力1を払う。`reset` は着手中の進捗を捨ててbacklogへ戻す。`restart` は `saved` を現行intakeと同様に進捗0で着手し、保存を消す。`saved` に対する `start` は拒否する。

差引=成果−緊急の期限代償−集中力。単位を等価とする暫定指標で、本番の評価式ではない。

継続は機能を先に完成させる。完了間近はtick2、初期段階はtick5で価値22を得るが、緊急はtick4またはtick7に終わり期限3を外して代償6。差引16。保存再開は最初に機能を保存し、緊急をtick3で価値14、その後に保存進捗へ戻る。完了間近は集中力2で機能も期限内に終わり差引34。初期段階は期末に進捗5/6で機能が未完、差引12。切替の利益は完了間近で+18、初期段階で−4。

進捗を捨てる切替はどちらも緊急だけを救い、機能は進捗5で未完、差引14。完了間近では保存再開に負ける。初期段階では、1進捗を残すための集中力2が完成に届かず、捨てた切替が保存再開を上回る。intake再初期化は保存した進捗を0に戻すため、完了間近の差引13は保存再開34に届かない。

`work-checkpoint-comparison.json` に同じ初期状態・入力列・結果を記録した。保存と再開の繰り返しでは進捗が増えない。固定係数の比較であり、面白さの証明ではない。保存容量、再開tickの長さ、緊急の出現時刻の感度は次節。初回の4戦略表はそこでは再計算しない。

## 要因を一つずつ動かした比較

固定戦略の計算である。人間のプレイ評価はしていない。途中で手を変える適応の証拠にはしない。本番採用の結論は出さない。

資源は初回と同じ。seed `RI-175`、期末8、集中力4、Coding枠1。機能は工数6・期限内価値22・期限7・期限後価値4。緊急は工数2・価値14・期限3・代償6。開始進捗4を完了間近、開始進捗1を初期段階とする。差引は成果−緊急の期限代償−集中力。未完了の機能価値は足さない。数値は本番定数ではない。

比べる手は継続、保存して再開、進捗を捨てて切替。intake再初期化は初回JSONのまま再出力しない。固定戦略は緊急がbacklogに出てから切替える。出現前は機能を進める。先回りして保存する手は含まない。

基準は保存容量6、再開1tick、出現tick0。容量6は機能工数と同じで、未完了の進捗を削らない。再開1tickは進捗を増やさず集中力1。出現0は最初からbacklog。動かした要因以外は変えない。基準行の三手は初回の継続・保存再開・切替と一致する。継続の差引は、緊急の期限を3のままにしたこの掃引では常に16。機能を先に終えると緊急は期限に間に合わない。

次に解く不確実性: 固定戦略は緊急が現れてから切替えるため、出現tick1では緊急が期限3に間に合わない。出現前に保存する先回りなら、完了間近の保存再開が上のままかどうかは未検証。

この要因比較は本番採用の判断を変えない。仮説は条件付き採用のまま、本番統合は保留。
