# RI-204 仕事の進め方が補い合う編成

対象は [#600](https://github.com/nimiusrd/devops-tycoon/issues/600)。判断は **再試作**。大規模PRの手戻りを減らせるが、全件が大規模PRでも出荷の優位は一部の seed に依存した。プレイヤーには、実装が速い担当を Coding に置くか、引き継ぎで大規模PRの手戻りを抑えるかを選んでもらう。

## 成立条件と代償

- 稼働中の Coding と Review が一人ずつで、Coding が「巨大PR製造機」、Review が「レビュー鬼」のときに成立する。控えや休職中の人は稼働人数に含めない。同じ二人を入れ替えたり、同じレーンに置いたりすると成立しない。固定編成で担当を一意にできる盤面を対象にする。
- この二人を通る、Backlog から始める大規模 PR（`complex`）だけ、Review 時の手戻りの式に既存のタスク別補正を適用する。現行の `split` 印を試作内部で使い、確率の減衰・上下限を適用する前に 0.16 を引く。組織初期値で初回の手戻り率は 7.64% から下限の 2% に下がる。印は同じ PR の再レビューでも残る。補正が直接変えるのは対象 PR の手戻り率だけ。
- 既存の個人トレイトは配置ごとに `foldFormationEffects` で畳み込む。ペアを組むと実効実装力は 65 で、入替時の 76 より低い。Coding 速度倍率は約 0.983 対 1.030、Review 効率倍率は 0.9342 対 0.935。担当を変える自由はあり、ペアを外す選択に追加の費用は付けない。

## 比較条件と入力

| メンバー | ランク・レベル | 実装 / レビュー / AI習熟 | 初期スタミナ | ペア配置 | 入替配置 |
| --- | --- | ---: | ---: | --- | --- |
| 作り手（巨大PR製造機） | ミドル Lv.1 | 52 / 47 / 44 | 85 | Coding | Review |
| 見直し役（レビュー鬼） | ミドル Lv.1 | 76 / 52 / 44 | 85 | Review | Coding |

- 配置以外は同じ二人。同じ人数・基礎能力合計（実装 128、レビュー 99、AI習熟 88）、同じ初期組織・タスク・乱数 seed で、ペア・ペアの補正なし・担当入替の三つを比較する。
- 標準シナリオから AI を無効にして開始し、並列枠 3、タスク 16 件、終了判定の上限は tick 55（tick 0 から最大 56 回更新）。16 件はすべて Backlog から開始。カードや追加資源、スプリント中の介入は使わない。生成時の高価値抽選を残して、規模は各4件のうち先頭 0 / 2 / 4 件を大規模、残りを中規模にする。
- seed は `RI-204:1`〜`RI-204:12`。本番の `createSprint` と `stepSprint` を回し、終了後の個人スタミナは `applySprintGrowth` で算出する。seed の開始位置は共通で、工程順や完了・手戻りが変わると、その後の乱数を引く順も変わり得る。
- [比較JSON](complementary-traits-comparison.json) に初期組織・設定・seed 別の高価値タスク ID と、各条件の出荷、完了数、手戻り、障害、最大レビュー待ち、終了までの更新回数、残スタミナを記録した。

## 結果

各セルは12 seed の平均。出荷はコンボと高価値タスクを含む点数。完了は件数。

| 大規模PR | 配置 | 出荷 | 完了 | 手戻り |
| ---: | --- | ---: | ---: | ---: |
| 0件 | ペア | 148.75 | 14.92 | 0.83 |
| 0件 | ペア・補正なし | 148.75 | 14.92 | 0.83 |
| 0件 | 入替 | 149.33 | 14.92 | 0.83 |
| 8件 | ペア | 183.42 | 13.83 | 0.42 |
| 8件 | ペア・補正なし | 179.83 | 13.50 | 0.83 |
| 8件 | 入替 | 192.33 | 14.75 | 0.75 |
| 16件 | ペア | 174.50 | 11.33 | 0.17 |
| 16件 | ペア・補正なし | 169.17 | 11.17 | 0.58 |
| 16件 | 入替 | 171.50 | 11.42 | 0.58 |

大規模 PR が 8 件では、補正でペアの手戻りが減っても、Coding が速い入替のほうが12 seed 中11 seed で多く出荷し、1 seed で同点だった。大規模 PR が16件では、補正ありのペアが平均出荷点で入替を3点上回る。seed 別ではペア3勝、同点7、入替2勝で、`RI-204:4` の +42 点を外すと、残り11 seed の平均差はペア側が約 -0.55 点になる。完了件数は16件の条件でも入替が僅かに多い。全試行で回復前の残スタミナは、作り手 / 見直し役の順に、ペアが 63 / 48、入替が 57 / 55。レビュー鬼を Review に固定すると見直し役の残量が7減る。

## 次の判断

新しい seed で実装の持ち時間と大規模PRの比率を別々に変え、出荷点・完了数・スタミナを比較する。単独 seed を外しても編成の選び分けが残るかを再確認する。続けて編成画面上の試作で、始める前に対象タスクと担当固定の代償を見て、別々の盤面で参加者が編成を選び分けられるかを確かめる。今回は固定方針の計算で、人間のプレイ評価は未実施。

試作盤面・組織・PRNG状態のJSON往復で同じ結果に再開できる。通常ランのロスター、保存、リプレイ、ruleset への接続は本番採用を判断した後の設計事項。特に複数人が各レーンにいる場合は、実タスクの担当の表現と、既存のPR分割補正との合成を決める必要がある。
