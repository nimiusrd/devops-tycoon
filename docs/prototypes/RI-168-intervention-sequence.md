# RI-168: 原因に沿った介入連携

対象 #564 / 親 #548。#562 / PR #760 の子タスク分割モデルを共用するstacked PR。結論: **手順・対象・期間による差の仮説を限定採用、本番統合は保留**。人間のプレイ評価は未実施。

## 2手と状態変化

既存のPR分割→ペアレビューを簡略化した純TS試作。通常ランの実際のペアレビューはReview先頭数件へ作用するため、対象指定と境界確認はこの試作固有の仮説。現行操作に同じ効果があるとは扱わない。

RI-166と同じ1担当・集中力6・親の残工数4/価値12、分割費2、子2件＋統合1件。seed `RI-168` は固定盤面識別子で乱数なし。統合の初回失敗が予定される同じ盤面を、期末3/9tickで比較。別系統otherは価値0の対照で、分割対象から除外して無消費で拒否する。比較方針はparentの仕事だけ進める。

分割で親の構造を改訂し、投入済み仕事を廃棄して子を生成する。ペアレビューは集中力2と担当の1tickを使って境界を確認する。同系統の確認完了時点が分割後2tick以内・失敗前・未完了子への確認なら、その新しい構造の統合リスクを解消し、初回失敗による追加2工数が不要になる。子の仕事や統合の基本2工数を飛ばしたり、独立したスコア/連携ボーナスを与えたりしない。

逆順では古い親構造の確認になり、後の分割が新しい境界を作るため統合リスクは残る。別系統や2tick超の確認でも当該系統の統合リスクは変わらない。対象/期間外の有効入力は確認費を払うが成果は加算しない。同系統・同構造の二度目は別の子を選んでも無消費で拒否する。未知・退役・Done・統合タスク・資源不足・期末も拒否。分割された親を操作して報酬を重ねられない。

2tickという期間は分割直後に境界を確認できるという仮定であり、本番の時間定数ではない。状態の親子・構造改訂・確認済み・分割時刻から効果を導出するが、実際の仕様/コード境界のモデルは未導入。
