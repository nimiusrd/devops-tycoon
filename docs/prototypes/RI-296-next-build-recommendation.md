# RI-296 次に試す運営方針の提案

対象は #692、親課題は #548。判定は **再試作**。今回は保存済みリプレイに基づく提案の根拠、履歴が少ないときの扱い、解放条件の参照を検証した。

## 選ぶ方針と代償

プレイヤーはこれまでの組み合わせを続けるか、次のランで別の施策に投資するかを選ぶ。

| 方針 | 目指すこと | 代償 |
| --- | --- | --- |
| 自動テスト強化＋静的解析導入 | 手戻りを抑える | 整備に集中力を使い、短期の実装速度が落ちる |
| PRサイズ制限＋レビューBot導入 | 小さい変更のレビューを回しやすくする | 発動に集中力を使う。Botが未解放なら解放にもポイントが要る |

## 履歴と提案

`recommendNextBuild(replays, meta)` は RI-293 の `summarizeBuild` を使い、現行ルールセットと版・指紋が一致する決着リプレイの終端デッキを読む。片方ずつ別のランで取得していても、2枚の組み合わせを取得した根拠にはならない。中間のカード発動、プレイヤーの上手さ、勝利確率は推定しない。取り込んだリプレイを含め、根拠は「参照した記録に残る組み合わせ」として扱う。入力にないランや、上限を超えて削除された記録には判断を広げない。

- どちらの組み合わせも確認できなければ、解放済みの案を優先した一般候補を返す。根拠の種別は `general` になる。
- 一方だけ確認できれば、残る一案と、確認できた組み合わせのカードID・リプレイIDを返す。根拠の種別は `recorded-alternative` になる。
- 両方を確認できれば提案なし。現行ルールセットと照合できない記録や、結果に対応する終端フレームのない記録は判定から外す。

未解放カードがあれば、既存カタログの解放ID、必要ポイント、前提実績を返す。現在のレビューBot導入には30ポイントが必要。解放済みのカードはドラフト／ショップのプールに入る。試作に購入、貸与、研修方針の反映、ラン開始、通信、永続化の処理はない。

## 検証と再試作条件

テストでは同じ seed `g1`、難易度 Normal、試練なし、初期予算45、4枚の候補プールで実際の RunEngine を決着まで進める。取得入力は対象カードが候補に出た最初の機会に選び、その他のドラフトをスキップする固定方針。取得済みカードは既存の自動プレイ手順で使う。終端に品質側の2枚が揃う場合は小型PR側を、逆の場合は品質側を提案する。候補プールを絞ったテストなので、通常の出現頻度や戦略の優劣の比較には使わない。

この試作では、提案が操作の代償を理解する助けになるか、人間によるプレイ評価を行っていない。次回は隔離した開始画面で履歴あり／不足／未解放の各状態を提示し、プレイヤーが提案理由を参照先の記録から説明できること、一般候補を個人評価と誤解しないこと、提案を無視して普段どおり開始できることを確認する。本番統合とIssueのクローズはその検証後に判断する。
