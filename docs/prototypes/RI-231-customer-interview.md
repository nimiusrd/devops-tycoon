# RI-231: 短納期と不確実な要望で、即着手と聞き取りを比べる

対象 #627 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。優劣が反転する位置は要因比較に記録した。人間のプレイ評価は未実施。本番採用の結論は出さない。

## 固定盤面と聞き取り

通常ランから隔離した純TS試作。seed `RI-231` は盤面識別子で乱数は使わない。余力は RI-228 の4。依頼者は RI-229 の固定ロスターで、短納期は新機能が多い3対1、不確実と有力候補が外れる盤面は安定が多い1対3。機能は api、screen、billing。必要量は4なので、1期間で1機能が完成する。正しい機能の完成価値は12で一度だけ。期限後の完成は10を引く。敗北状態にはしない。自由会話や外部モデルは使わない。

聞き取り前の閲覧は、噂の api と不明な需要だけを示す。真の需要と、まだ返していない候補は閲覧に出さない。聞き取りは1期間の余力4を使い、盤面に別に置いた有力候補と未確認候補を返す。有力候補は真の需要からコピーしない。二度目の聞き取りは状態を変えない。

短納期の真の需要は api、有力候補も api、期限は最初の1期間。不確実な盤面の真の需要と有力候補は screen、期限は3期間。有力候補が外れる盤面の真の需要は billing、有力候補は screen、未確認候補は billing、期限は3期間。即着手は噂の api を作る。聞き取りは確認してから有力候補を作る。別候補は確認してから未確認候補を作る。

## 同条件比較

差引は完成価値−期限遅れ。聞き取り費用は失った期間として結果に残り、差引からは二重に引かない。

| 盤面 | 即着手 | 聞き取り | 聞き取り後の別候補 |
| --- | ---: | ---: | ---: |
| 短納期 | 12 | 2 | 0 |
| 要望が不確実 | 0 | 12 | 0 |
| 有力候補が外れる | 0 | 0 | 12 |

短納期では即着手の12が、聞き取り2と別候補0を上回る。噂が正しく、確認に期間を使うと完成が期限を外す。要望が不確実な盤面では聞き取りの12が、即着手0と別候補0を上回る。有力候補が外れる盤面では別候補の12が、聞き取り0と即着手0を上回る。有力候補に従っても報酬はない。

固定3盤面の仮説比較であり、本番の面白さや一般的優位の証明ではない。期限、確認費用、候補の組み合わせの感度は次節。初回の3盤面表はそこでは再計算しない。

## 要因を一つずつ動かした比較

固定戦略の計算である。人間のプレイ評価はしていない。固定手順の差引を、本番の面白さやプレイヤーが境界を見て選べることの証明にはしない。本番採用の結論は出さない。

資源は初回と同じ。seed `RI-231`、期間は3、余力は4、必要量は4、完成価値は12、期限遅れは10、噂は api。機能は api、screen、billing。依頼者の構成は盤面プリセットのまま。差引は完成価値−期限遅れ。確認費用は余力×確認期間で、差引には入れない。即着手は毎期間、噂を作る。聞き取りは一度確認し、その後は有力候補を作る。別候補は一度確認し、その後は未確認候補を作る。優劣は聞き取りと即着手の差引で決める。同じなら同点。別候補が最大でも、二人が同じなら優劣は同点である。別候補は結果を見て選んだ手ではない。動かした要因以外は変えない。盤面名は、期限と候補が初回のプリセットと一致する行ではその盤面、それ以外は列の基準盤面である。確認期間は盤面名に使わない。各行の数値は rules が正。数値は本番定数ではない。

閲覧は期限を返す。確認期間は閲覧に出さない。真の需要は閲覧に出さない。確認期間1は状態に `askTicks` を足さない。上書きしたときだけ保存し、初回の比較JSONの形は変えない。期間0は感度の端であり、基準規則ではない。期間0でも聞き取りは真の需要を返さず、有力候補と未確認候補だけを返す。

即着手は、噂が需要と一致するとき、完成tick 0が期限未満なら12、以上なら2。一致しなければ0。聞き取りは、有力候補が需要と一致し、確認期間が3未満のとき、完成tickである確認期間が期限未満なら12、以上なら2。それ以外は0。別候補は未確認候補で同じ式。期限0でも完成すれば価値は入り、遅れ10を引いて2になる。敗北にはしない。

期限だけを動かす。確認期間は1。候補は各盤面の初回のまま。

| 期限 | 即着手 | 聞き取り | 別候補 | 聞き取りと即着手 | 最大 |
| ---: | ---: | ---: | ---: | --- | --- |
| 0 | 2 | 2 | 0 | 同点 | 即着手と聞き取り |
| 1 | 12 | 2 | 0 | 即着手 | 即着手 |
| 2 | 12 | 12 | 0 | 同点 | 即着手と聞き取り |
| 3 | 12 | 12 | 0 | 同点 | 即着手と聞き取り |

短納期。需要は api、有力候補も api、未確認候補は billing。期限1は初回と一致する。反転は期限0と1のあいだで即着手へ移り、1と2のあいだで同点に戻る。即着手が上回るのは、即着手だけが期限内に終わるとき。期限0は両方とも遅れ、期限2以上は両方とも期限内である。聞き取りが即着手を上回ることはない。

| 1 | 0 | 2 | 0 | 聞き取り |
| 2 | 0 | 12 | 0 | 聞き取り |

要望が不確実。需要は screen、有力候補も screen。期限3は初回と一致する。反転しない。噂が需要と違うため即着手は0のまま。期限が1以下でも聞き取りの差引2が上回る。

| 期限 | 即着手 | 聞き取り | 別候補 | 聞き取りと即着手 | 最大 |
| ---: | ---: | ---: | ---: | --- | --- |
| 0 | 0 | 0 | 2 | 同点 | 別候補 |
| 1 | 0 | 0 | 2 | 同点 | 別候補 |
| 2 | 0 | 0 | 12 | 同点 | 別候補 |
| 3 | 0 | 0 | 12 | 同点 | 別候補 |

有力候補が外れる。需要は billing、有力候補は screen、未確認候補は billing。即着手と聞き取りは0の同点のまま反転しない。別候補は期限2以上で12。期限3は初回と一致する。

確認期間だけを動かす。0は期間を使わない端。短納期の期限は1、他の二盤面の期限は3。候補は各盤面の初回のまま。即着手の入力列は変わらない。確認期間が増えると、聞き取りと別候補のあとに残る着手が減る。

| 期間 | 即着手 | 聞き取り | 別候補 | 聞き取りと即着手 |

| 1 | 12 | 2 | 0 | 即着手 |
| 2 | 12 | 2 | 0 | 即着手 |
| 3 | 12 | 0 | 0 | 即着手 |

短納期。期間1は初回と一致する。反転は期間0と1のあいだで同点から即着手へ移る。候補が一致しているので、期間を使わなければ両方とも期限内の12になる。期間を1以上にすると聞き取りの完成が遅れ、期間3では完成しない。増やす方向では即着手が上のまま、さらなる反転はない。

| 期間 | 即着手 | 聞き取り | 別候補 | 聞き取りと即着手 | 最大 |
| ---: | ---: | ---: | ---: | --- | --- |

要望が不確実。期間1は初回と一致する。反転は期間2と3のあいだで聞き取りから同点へ移る。期限3なので確認2期間でも完成tick 2は期限内。確認3期間は期間を使い切り、完成できない。即着手は0のままなので、即着手が上回ることはない。

| 期間 | 即着手 | 聞き取り | 別候補 | 聞き取りと即着手 | 最大 |
| ---: | ---: | ---: | ---: | --- | --- |

有力候補が外れる。即着手と聞き取りの優劣は反転しない。別候補は確認3期間で完成できず、最大ではなくなる。期間1は初回と一致する。

候補の組み合わせだけを動かす。噂は api、未確認候補は billing、確認期間は1。各段は直前から需要か有力候補の一方だけが変わる。`both-correct` は噂も有力も正しい。`likely-wrong` は有力だけが違う。`likely-correct` は有力だけが正しい。`other-correct` は未確認だけが正しい。未確認候補だけを変えても、即着手と聞き取りの差引は動かない。

| 組み合わせ | 需要 | 有力 | 即着手 | 聞き取り | 別候補 | 聞き取りと即着手 | 最大 |
| --- | --- | --- | ---: | ---: | ---: | --- | --- |
| both-correct | api | api | 12 | 2 | 0 | 即着手 | 即着手 |
| likely-wrong | api | screen | 12 | 0 | 0 | 即着手 | 即着手 |
| likely-correct | screen | screen | 0 | 2 | 0 | 聞き取り | 聞き取り |
| other-correct | billing | screen | 0 | 0 | 2 | 同点 | 別候補 |

期限1。短納期の期限と確認期間。`both-correct` は初回の短納期と一致する。有力候補を api から screen にしても即着手が上のまま。需要を screen に移すと聞き取りへ反転する。需要を billing に移すと同点に戻る。この同点では別候補の2が最大である。

| 組み合わせ | 需要 | 有力 | 即着手 | 聞き取り | 別候補 | 聞き取りと即着手 | 最大 |
| --- | --- | --- | ---: | ---: | ---: | --- | --- |
| both-correct | api | api | 12 | 12 | 0 | 同点 | 即着手と聞き取り |
| likely-wrong | api | screen | 12 | 0 | 0 | 即着手 | 即着手 |
| likely-correct | screen | screen | 0 | 12 | 0 | 聞き取り | 聞き取り |
| other-correct | billing | screen | 0 | 0 | 12 | 同点 | 別候補 |

期限3。不確実な盤面と、有力候補が外れる盤面の期限と確認期間。`likely-correct` は初回の不確実な盤面、`other-correct` は初回の有力候補が外れる盤面と一致する。反転は同点から即着手、即着手から聞き取り、聞き取りから同点の三段。期限に余裕があると、噂も有力も正しいときは同点で、有力だけを外すと即着手が上回る。未確認だけが正しい段の同点では、別候補の12が最大である。

`customer-interview-factor-comparison.json` に条件、規則、初期状態、入力列、差引、優劣、反転を残す。対象テストが再計算し、期限・確認期間・候補が初回の基準と一致する行が初回JSONの即着手・聞き取り・別候補と一致することを照合する。初回の比較JSONは更新していない。

次に解く不確実性: 有力候補が外れたあと残期間で未確認候補も作る適応にすると、未確認だけが正しい組み合わせで即着手と聞き取りの同点が残るかは未検証。

この要因比較は本番採用の判断を変えない。仮説は限定比較の採用のまま、本番統合は保留。

## 本番境界と検証

顧客の自由会話、ネットワーク、外部の言語モデル、勝敗へは接続しない。閲覧順で結果は変わらない。通常の編成、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。本番採用時は聞き取り済みの保存、閲覧から真の需要を除く契約、期限遅れと確認費用の分離を別Issueに分割する。version 1の信頼済み内部JSONには再現のため真の需要を含める。外部入力検証と通常保存互換は対象外。

`customer-interview-comparison.json` に初期状態、入力列、完成価値、期限遅れ、確認費用、差引を記録した。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。要因比較は Node 24 で対象ユニット、保存再開と入力再生、lint、format:check。UI/Pixiの変更はなく、E2Eとgalleryは対象外。通常ランの本番、UI、保存、rulesetへは接続していない。customerSegments と customSharedOrder は変更していない。
