# RI-188: 施策廃止と「持ち込まない」の比較

対象: #584、親: #548。依存: #583の持ち込み試作（PR #746）。評価: **現行の効果・維持費モデルのままでの本番採用は見送り**。

## 最小試作

スプリント間で所持カード1枚を廃止し、移行費用として予算5を払う。1スプリント境界につき1枚、最低有効所持枚数3。予算を0以下にする廃止は拒否する。所持インスタンスの位置を廃止台帳に残し、カード配列を詰めて他カードのID・レベル・baseline台帳をずらさない。同じ定義IDの別インスタンスは影響を受けない。

廃止後は次スプリントの候補・手札・山札に入らず、通常の選び直しで復活できない。所持記録自体は墓標として保持する。候補3枚からの廃止で候補下限を割る場合、明示的な次候補が指定されるまで操作を拒否し、勝手に代替カードを追加しない。進行中、同じ境界で2枚目、無効対象、費用不足、不正候補では費用を消費しない。

## baselineと既得効果

**恒久加算は正負とも残す**。既にAI依存度が増え、セキュリティが下がった投資を廃止しても巻き戻さない。品質・リテラシーなどの正側も残す。clampされた基準値から導入分を正確に逆算できず、他カード・イベント・チームの加算が混ざるため、現行の `baselineAppliedLevel` / `baselineAppliedByTeam` のレベルだけで返却しない。

失う利益は、次スプリント以降のカード発動による速度・レビュー・障害率などの局所効果、将来の強化・再持ち込みの選択肢。同時にそれらの局所的な負作用も発動しなくなる。移行費用の返金、施策復活、恒久加算の再取得操作は作らない。廃止台帳と適用台帳を保存するので、保存再開や同じ操作の再送で費用・効果を増やさない。

## 対照比較と結論

#583の同一所持6枚・資源・実工程を使用する。seedは `RI-188`、`RI-188:1`、`RI-188:2`。大型リリース向けはレビューBot、監査向けはCopilotの1枚を対象にする。次の3方針を比較する。

- 維持: 所持6、候補6、移行費用0。
- 未持ち込み: 所持6、候補5、移行費用0。別スプリントで再び選べる。
- 廃止: 有効所持5、候補5、移行費用5。別スプリントでも再び選べない。

共通方針は目的カードが手札にあれば1枚発動し、無ければ先頭1枚。残集中力を割り込みレビューへ回す。交換は使わず、候補削減だけの影響を見る。配布乱数は持ち込み試作と同じ正規化・seedを使う。

3seed×2条件すべてで、**未持ち込みと廃止は実手札・出荷・品質・集中力消費が一致**する。廃止だけ予算20→15と将来の1枚を失う。カードを削って引きが改善することはあっても、その改善は費用不要の未持ち込みで得られる。全手札・効果・費用は `card-retirement-comparison.json` に保存し、テストで再生成する。

現行カードには所持だけで払う維持費がなく、廃止の返却益を追加する根拠もない。したがって持ち込み選択と同時に入れる場合、この案は有料の劣位操作になる。**このルールの本番採用は見送る**。台帳・費用の最小試作は残すが、操作UIを増やさない。プレイヤーが新構成を試す価値はまず#583の可逆な持ち込みで評価する。

将来、#579の運用枠や#581の使って育つ施策などが所持コストを実際に持つ場合だけ再評価する。その場合も維持費を廃止に有利な数値へ恣意的に追加せず、維持した成果・運営負担・解放した枠を同じ基準で比べる。

## 保存・本番への境界

通常ラン・ruleset・本番保存・UIは変更しない。試作専用 `version: 1` は所持位置、廃止台帳、最後に廃止した境界、予算、持ち込みと現スプリントをJSONで保持する。本番に再検討する場合、個体カードの安定ID、廃止台帳の保存/リプレイ検証、購入時の新インスタンスとの区別、複数チームのbaseline継承、SPEC・対応表更新を先に設計する。

## 検証

Dev Containerで廃止・持ち込み・手札交換のユニット、型チェック、lint、format:checkを実行。同IDの別インスタンス、正負baseline保持、最低枚数、費用不足、進行中と重複操作の拒否、次スプリント反映、JSON保存再開、未持ち込みとの同条件比較を検証。UI/Pixi変更なしでE2E・galleryは対象外。
