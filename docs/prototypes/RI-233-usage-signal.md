# RI-233: 観測した利用で、追加投資と撤退を比べる

対象 #629 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と利用

通常ランから隔離した純TS試作。seed `RI-233` は盤面識別子で乱数は使わない。余力は4。反応する人数は RI-229 の固定ロスター4人で、期間中に増えない。機能は api、screen、billing の3つで、各機能の完成作業は5、出荷量は15である。3つの観測で出荷量と予測は同じで、予測は各機能3。期間は4。利用0の機能を閉じると保守枠8が一度戻る。利用1以上の機能を直すと、その利用に1を足した値が一度入る。実際の利用は人数以下である。敗北状態にはしない。

閲覧は実際の利用を出さない。操作前に示すのは、出荷量、予測、撤退値8、改善の上乗せ1、余力、人数である。出荷は機能を公開するだけで、利用も価値も付かない。利用は観測したとき一度だけ見え、二度目の出荷、二度目の観測、同じ機能の再改善は状態を変えない。観測前の改善は拒否する。

予測のまま投資する手順は、出荷のあと予測の同点を api とみなし、残りの各期間でその機能の実際の利用を得る。観測はしない。追加投資は、出荷してから観測し、見えた最大利用へ残りの期間を入れる。改善撤退は、出荷してから観測し、見えた最小利用を一度だけ直し、次の期間に公開済みの値を一度得る。同点は api、screen、billing の順で先にある機能を選ぶ。

## 同条件比較

行の中だけを比べる。出荷量はどの行も15である。

| 観測 | 実際の利用（api, screen, billing） | 予測のまま | 観測して追加 | 観測して改善 |
| --- | --- | ---: | ---: | ---: |
| 予測の先頭が伸びる | 4, 1, 1 | 12 | 8 | 2 |
| 予測の先頭が外れ、別機能が伸びる | 1, 2, 4 | 3 | 8 | 2 |
| 一つが使われず、残りは分かれる | 1, 3, 0 | 3 | 6 | 8 |

予測の先頭が当たる観測では、観測に使う1期間のため、予測のまま12が追加8と改善2を上回る。改善の対象は screen で、得られるのは2である。予測の先頭が外れる観測では、観測して billing へ追加する8が、予測のまま3と api の改善2を上回る。利用0がある観測では、billing を閉じる8が、screen への追加6と予測のまま3を上回る。

同じ出荷量でも、見えた利用が一つに偏るか、予測と違う機能が伸びるか、使われない機能があるかで、次に選ぶ手が変わる。固定3観測の仮説比較であり、本番の利用計測の証明ではない。次は撤退値、観測に使う期間、予測の偏りの感度を見る。

## 本番境界と検証

製品の販売、勝敗、画面更新による利用の引き直しへは接続しない。閲覧順で結果は変わらない。通常の編成、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。本番採用時は出荷済みと利用観測の保存、閲覧から実際の利用を除く契約、完成と利用の分離を別Issueに分割する。version 1の信頼済み内部JSONには再現のため実際の利用を含める。外部入力検証と通常保存互換は対象外。

`usage-signal-comparison.json` に観測、初期状態と入力列、得点を記録した。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
