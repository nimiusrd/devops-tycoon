# RI-178: 二人で一件を進める

対象 #574 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と操作

通常ランから隔離した純TS試作。seed `RI-178` は盤面識別子（乱数なし）。期末6、Coding枠2。単独は1枠、ペアは2枠を確保する。どちらも進捗は1tickにつき1で、ペアは二人分の速度にはならない。空き枠が必要数未満なら開始できず、ペア中に別件の単独も開始できない。

複雑な単独は工数を終えたあと、同じ1枠を持ったまま手戻り2tickを行う。手戻りへ入ったtickでは手戻りを進めない。ペアと定型仕事は手戻りなしで、完成時に確保枠を一度だけ戻す。中断も確保枠を一度だけ戻し、進捗は残す。手戻りの途中で枠を追加確保しない。

複雑盤面は仕事3件、各工数2・価値14。定型盤面は仕事6件、各工数2・価値8。方針は、空き枠が足りるあいだペアまたは単独で未着手を始め、足りなければtickする。人物の相性と恒久育成は置かない。

## 同条件比較

| 盤面 | すべて単独 | すべてペア |
| --- | ---: | ---: |
| 複雑3件 | 28 | 42 |
| 定型6件 | 48 | 24 |

差引=完成した仕事の価値。未完了は0として数える。

複雑では単独が2件を手戻り込みで完成して28、3件目は期末に手戻りへ入ったまま。ペアは手戻りを省いて3件42。定型では品質差がなく、単独が2枠で6件48、ペアは1件ずつしか進まず3件24。同じ枠ルールでも、手戻りがある仕事が多いか、定型が多いかでペアの優劣が入れ替わる。

`pair-work-comparison.json` に初期状態、入力列、確保・解放・手戻りtick、結果を記録した。比較中の空き枠と保持枠の合計は常に2。完成と中断では、その着手で確保した枠数だけが解放される。固定係数の比較であり、面白さの証明ではない。次は複雑仕事だけをペアにする混合方針と、ペアが速度も上がる条件を分ける。

## 本番境界と検証

現行 `pair-programming` カードは手戻り率、コーディング速度、品質の係数を会社全体へ乗せる。本件はその係数を、枠を実際に使う工程ルールへ置き換える候補。元案054の師弟と元案052の相性は含めない。#538の育成ループとも別物。通常Task、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。本番採用時は途中の枠表示、手戻り再開、カード係数との置換を別Issueで設計する。version 1の信頼済み内部JSONのみ。外部入力検証と通常保存互換は対象外。

対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
