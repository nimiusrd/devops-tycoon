# RI-190: 計画してから実装

対象 #586 / 親 #548。#585 / PR #778 の仕事盤面を使うstacked PR。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と操作

通常ランから隔離した純TS試作。seed `RI-190` は盤面識別子（乱数なし）。RI-189の仕事盤面を人間速度（進捗1、利用費0）で進める。計画は2tickで、その間は対象仕事の進捗も出荷も増えない。1tickだけでは発見を返さない。2tick目に、複雑な仕事は `dependency:ledger-order`、単純な仕事は `no-hidden-scope` を記録する。計画が完了した仕事だけ作業量が6のままになる。

未計画の複雑な仕事は、最初の実装tickで作業量6が9になり、完了時に価値6を迷走ペナルティとして一度だけ引く。単純な仕事は未計画でも作業量も価値も変わらない。計画は未着手かつ未計画の先頭仕事だけを受け付ける。着手後、計画済み、別仕事の計画中、期末は無消費で拒否する。予算0のためRI-189の高速モデル割当も拒否される。閲覧では計画も実装も進まない。

比較方針は公開情報だけを使う。`plan` は先頭の未計画仕事を2tick計画してから実装する。`rush` は計画せず実装する。

## 同条件比較

| 盤面 | 即着手 | 先に計画 |
| --- | ---: | ---: |
| 単純・期末6 | 10 | 0 |
| 複雑・期末8 | 0 | 18 |
| 複雑・期末12 | 12 | 18 |

差引=出荷価値。利用費は0。単位を等価とする暫定指標。

単純で短い期末では、計画2tickのあと実装が4しか進まず未完了の0。即着手は価値10を出荷する。計画の発見は `no-hidden-scope` で、遅れだけが残る。

複雑な期末8では、未計画の作業量9が期末を超えて0。計画すると作業量6のまま期末ちょうどで18。同じ複雑さでも残り時間で優劣が入れ替わる。

複雑な期末12では両方完了する。即着手は迷走ペナルティで12、計画は発見を残したまま18。計画の価値は「間に合うか」と「完了後の手戻り」の両方に出る。

`implementation-plan-comparison.json` に初期状態、入力列、発見、迷走、解決順を記録した。固定係数の比較であり、面白さの証明ではない。次は計画tick数と迷走量の感度を見る。

## 本番境界と検証

#552の仕様調査は、未知の要件を調べる行為。本件は既知仕様に対する実行計画で、実LLMは呼ばない。RI-189のモデル割当は盤面として使い、この段では予算を0に固定して計画の有無だけを比べる。通常の工程、カード、勝敗、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。本番採用時は計画中の表示、保存された発見、入力再生を別Issueで設計する。version 1の信頼済み内部JSONのみ。外部入力検証と通常保存互換は対象外。

対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
