# RI-193: エージェントの権限設定

対象 #589 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定盤面と操作

通常ランから隔離した純TS試作。seed `RI-193` は盤面識別子（乱数なし）。権限はゲーム内の `read` と `edit` だけ。実端末、OS、GitHubの権限は操作しない。方針の設定はtickを消費せず、最初の作業の前だけ変更できる。未知の権限、同じ権限の再設定、着手後の変更、権限なしの進行、期末は無消費で拒否する。

定型仕事は作業量4、価値6。`read` は進捗1、`edit` は進捗2。重要仕事は作業量4、価値16。`read` は最初の2tickを承認待ちにして進捗を増やさない。`edit` は承認なしで進捗2だが、完了時に影響20を一度だけ引く。閲覧は各仕事を `approval` か `allowed` で示す。

比較方針は公開情報だけを使う。`read` と `edit` は最初にその権限を置いてから、未完了の先頭仕事を進める。

## 同条件比較

| 盤面 | edit | read |
| --- | ---: | ---: |
| 定型2件、期末6 | 12 | 6 |
| 重要1件、期末8 | -4 | 16 |

差引=出荷価値−影響。単位を等価とする暫定指標。

定型では `edit` が2件出荷して12。`read` は1件と途中までで6。広い権限の速度が効く。

重要では `read` が承認2tickのあと16を出荷し、影響0。`edit` は2tickで16を出荷するが影響20で差引-4。同じ速度利益が、失敗時の影響で打ち消される。`edit` は上位互換ではない。

## 本番境界と検証

案47は領域別のAI利用方針、案73は人の承認委譲。本件はエージェントの作業範囲だけで、現実のセキュリティ設定は扱わない。通常の保存、ruleset、勝敗、SPEC、固定トラック、WebGL停止契約へ接続しない。本番採用時は権限の表示、保存、入力再生を別Issueで設計する。version 1の信頼済み内部JSONのみ。外部入力検証と通常保存互換は対象外。

対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
