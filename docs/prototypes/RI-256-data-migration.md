# RI-256: データ移行の早期切替と検証延長を比べる

対象 #652 / 親 #548。結論: **限定比較の仮説採用、本番統合保留**。人間のプレイ評価は未実施。

## 固定イベント

通常ランから隔離した純TS試作。seed `RI-256` は盤面識別子で乱数は使わない。移行対象は4、1tickの枠は2。準備中は、移行していない分を整合確認できない。確認枠を先に使っても確認は進まず、移行してから確認し直す。並行運用のtickは切替まで二重費用が積む。方針を選んだあとの手動配分も、そのtickの二重費用と切替判定を自動進行と同じにする。方針の前や切替後の手動配分は時間を進めない。移行が4に達すると切替できる。早期切替は確認が0でも切り替え、検証延長は確認が4に揃ってから切り替える。切替は後処理を同じ `migrated-batch` へ一度だけ適用する。切替後の修復は確認を1進め、二重費用・未検証リスク・後処理は再適用しない。確認が移行済みに追いついた修復は拒否する。開始直後の敗北にはしない。

盤面は二重費用と未検証リスクだけが違う。信頼できるデータは二重費用6、未確認1件のリスク1。敏感なデータは二重費用2、未確認1件のリスク8。出荷は切替できたとき20を一度だけ付ける。閲覧は、対象量、枠、二重費用、リスク、既存4ボスの出現率を変えないこと、両方の二重費用・リスク・得点を選択前に示す。決定後の選択肢は空になる。

## 同条件比較

得点は出荷から二重費用と未検証リスクを引いた値である。二つの費用は別々に残す。

| 盤面 | 確認前に切り替える | 確認が揃ってから切り替える |
| --- | ---: | ---: |
| 未確認のリスクが小さい | 4 | -4 |
| 未確認のリスクが大きい | -16 | 12 |

リスクが小さい盤面では、2tickで移行を終えて出荷20を取る。二重費用12と未確認4件のリスク4を引き、得点4になる。確認を揃えると4tickで二重費用24、リスク0、得点-4になる。リスクが大きい盤面では、早期切替は二重費用4でもリスク32が残り-16になる。確認を揃えると二重費用8、リスク0、得点12になる。早期切替が常に上位ではない。どちらの得点が負でも敗北にはしない。後処理は四つの結果とも1回で、切替後の待機tickでは増えない。

固定2盤面の仮説比較であり、本番のデータ移行ボスの証明ではない。次は、修復で減らせるリスクを切替後の得点へ戻すと、敏感なデータでも早期切替が上回るかを見る。

## 本番境界と検証

通常ランのボス抽選、全ボス実績、自動勝利、SPEC、保存、ruleset、固定トラック、WebGL停止契約へ接続しない。既存4ボスの出現率はこの試作では変えない。本番へ足すときは新しいボスIDを別rulesetで加え、古い保存は未遭遇として読む。閲覧順で結果は変わらない。version 1の信頼済み内部JSONに比較の初期状態、入力列、得点の推移を含める。外部入力検証と通常保存互換は対象外。

`data-migration-comparison.json` に盤面、初期状態と入力列、得点の推移を記録した。対象ユニット、毎入力のJSON保存再開と再生一致、型チェック、lint、format:checkを検証する。UI/Pixiの変更はなく、E2Eとgalleryは対象外。
