# RI-156: 曖昧な案件の仕様調査試作

対象: #552 / 親: #548。結論: **修正して再評価**。本番統合と人間のプレイ評価は保留。

## 情報と費用の境界

#551の期限価値と#550の固定盤面エンジンを共用するstack第3段。純TSの `specInvestigation.ts` は通常ランに接続しない。基本4工数、期限tick 4、期間6tick、集中力2、体力10。初期seedで予定リスクを一度決める。低リスクは手戻り0、高リスクは調査せず着手すると手戻り3工数。調査で高リスクの手戻りを回避する。曖昧さと調査操作は各1種。

調査前に見えるのは見積工数・期限・価値・調査費用。隠しリスクは保存用内部状態だけに持ち、プレイヤー向け投影はnullを返す。表示の開閉や読み取りは状態・乱数を変更しない。調査は2tickの全処理容量を譲り、集中力・体力は消費しない。途中ではまだリスクを公開しない。調査完了で対象案件のリスクと回避工数だけを公開し、別案件の情報レコードは更新しない。別案件自体の処理はこの初手ではモデル化しない。

調査中の入力は調査に使い、実装・追加作業は進まない。調査完了後の再調査・着手後の調査は拒否する。待機は調査前なら待機のまま、調査中なら調査を進める。資源不足の追加作業は着手・隠し工数・tickを確定しない。未調査で着手する場合は3工数を一度だけ追加し、表示にも残工数として反映する。工程別の手戻り発生tickはこの最小モデルでは分けない。

## 採否と次の評価

調査の費用と手戻り回避価値は比較できたが、この比較は**事後に内部リスクを分類した評価**であり、プレイヤーが調査前に高低を見分けられた証拠ではない。投影から予定リスクを漏らして状況選択を成立させてはいけない。そこで本番採用は判断せず、修正して再評価する。

次は作業領域や過去事例など公開された粗い兆候を追加し、同じ兆候でもseedで当たり外れがある盤面にする。複数seedで事前情報だけを使う方針と固定方針を比較し、調査の期待値・判断回数・機会費用を評価する。追加作業との組合せや別案件を進める選択も次の段へ分割する。現状で「調査が面白い」「高リスクを確実に選べる」とは結論しない。

## 保存・互換と検証

version 1のJSONに予定リスク・調査進捗・公開済みフラグ・着手済みフラグ・入力を持つ。調査途中の保存再開と入力再生は完全一致し、再開でリスクを振り直さない。投影は保存ではなく読み取り専用のプレイヤー向け情報境界。外部JSONの検証付きロードUIは対象外。

通常Task・介入パネル（#536）・SPEC・勝敗・固定トラック・保存・ruleset・描画は変更しない。本番採用時は新しい調査状態と予定リスクの保存移行、工程容量費用、既存介入との対象契約、表示を別Issueで設計する。発生済み障害の原因調査とは分ける。

Dev Container（Node 24）で3段のユニット、型チェック、lint、format:checkを実施。UI・Pixi・通常ランへの接続変更がないためE2E・galleryは対象外。
