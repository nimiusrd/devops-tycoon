### RI-67 オンボーディングとシニア燃え尽きの断絶

Easy でも無介入・素直プレイだと第1四半期スプリント2でシニア燃え尽き（`seniorBurnout`）敗北する。敗北条件は抽象値 `org.seniorHp <= 1`（`src/sim/outcome.ts:57`）で、メンバー個別 stamina ではない。`org.seniorHp` は毎 tick `REVIEW_HP_REGEN`=0.7（炎上中は半減）で回復し、主な減少要因はレビュー1件ごとの一律消費 `REVIEW_HP_COST`=1.6（`reviewOne`、`src/sim/sprint.ts:252`）と、猶予切れ炎上の自動鎮火 `INCIDENT_HP_COST`=12（`advanceBurning`、`src/sim/sprint.ts:340`）。スプリントは `isDrained` まで進むが、手戻り・鎮火タスクは Review へ再投入されるためレビュー回数はタスク数固定ではなく手戻り・炎上率で増減する。第1スプリント実測（同一 seed）では、自動鎮火回数と HP 終値が 無介入 3回/42、緊急対応のみ 1回/62、緊急対応＋andon 0回/74、編成＋介入 1回/55。最も確度の高い（単一条件変更の）要因は**炎上を自動鎮火 −12 の前に緊急対応 −2 で鎮火すること**。andon は流入を一時停止して既存キューを捌く猶予を作る補助。AIスロットルはレビュー1件あたりの点火率と手戻り率を下げ、品質・PR分割は手戻り率のみ下げて再レビューを減らす（点火率 `incidentProbability` は testCoverage・aiAssisted・カード効果のみ参照し品質値・`task.split` は参照しない）。編成（review 増員）は review 容量だけでなく Coding 担当減で `foldFormationEffects` の複数因子が連動するため単一機序に帰属できないが、A（編成のみ）は無介入と同じく即死しており燃え尽き回避の主手段ではない。チュートリアル（`src/ui/tutorial.ts`）は介入バー・レビュー渋滞・コンボのみで、燃え尽き回避の主手段を教えない。実測と経緯は[playtest-findings.md](./playtest-findings.md)参照。

受入条件:

- 初見プレイヤーがシニア燃え尽きを回避する最大手段（炎上を自動鎮火前に緊急対応で鎮火）へ導かれる。andon は既存キューを捌く猶予、AIスロットルは点火率と手戻り率を下げる、品質・PR分割は手戻り率のみ下げて再レビューを減らす、編成はスループット策であり燃え尽き回避の主手段ではない、と位置づけを区別する。
- チュートリアルまたは盤面・HUD の警告で、抽象値としてのシニア体力と燃え尽きリスクを事前に伝える。
- Easy の序盤（第1四半期）で、標準的な操作理解のプレイが2スプリントで即敗北しない。
- 難易度別の `org.seniorHp` 収支・レビュー負荷の妥当性を自動操作モデルまたはユニットテストで検証する。

### RI-72 難易度カーブと、単一介入が複合方針を上回る構造

難易度別の勝率（26方針 × 10ラン = 各260ラン）は easy 75% / normal 47% / hard 18% / nightmare 0%。SPEC 第19.1 F-7 が目標とする「初勝利5ラン前後＝勝率20%前後」に合うのは hard（初見相当 2/10）だけで、easy は完全放置（介入もカードも使わない）でも 7/10 勝てる。nightmare は260ラン全敗（RI-73）。

F-1 の違反は2方向にある。**単一介入の `onlyFirefight`（緊急対応のみ）が全26方針中トップの 22/40**（全難易度合計）で、複合方針の `skilled` 10/40・`skilledNoHire` 16/40 を上回る。難易度別でも easy 10/10・normal 8/10・hard 4/10 と、複合方針（5/10・4/10・1/10）より強い。緊急対応は「打てるときに打てば得」で状況によって正解が入れ替わらず、他の介入を選ぶ理由が薄い。なお全介入を 1 tick ごとに撃つ `probe` は 10/40 と弱く、乱打が損になる関係自体は成立している。

統制実験（同一 seed、条件を1つずつ外す）では、**採用が一貫して勝率を下げる**（全40ランで `skilled` 10 vs `skilledNoHire` 16。難易度別は easy 5/8、normal 4/5、hard 1/3）。採用方針を専用フェーズだけでなくショップの採用枠と即時採用イベントにも適用した結果、`RECRUIT_COST`=25 の負担が顕在化した。`budgetExhausted` 敗北は1,040ラン中30件。採用方針は専用フェーズ・ショップ・休息・即時採用イベントの全経路に適用済み。F-1 の観点では、緊急対応が「常に打てば得」であるのと対称に、**採用が「常に見送るのが正解」**になっている。一方カードは使い方を変えても勝率を動かさない（無差別 16 / 不使用 16 / 状況選択 15）。詳細は RI-77。

受入条件:

- 初見相当（`naive`）の勝率が概ね 20% 前後になる難易度が、導入難易度（easy / normal）側に存在する。
- 完全放置（介入もカードも使わない）で勝ち越せる難易度が無い。
- 単一介入だけを繰り返す方針が、状況に応じて介入を選ぶ方針を上回らない。緊急対応にも
  不利になる状況（打つべきでない盤面）が存在し、同一難易度の中で有利／不利が共存する。
- 採用が有利になる局面が存在する（現状は全難易度で見送るのが正解）。
- 各手段のコスト（採用の予算・カードの集中力）は F-1 の求める代償として維持する。求めるのは
  代償の消去ではなく、**代償に見合う状況が特定できること**である。
- 難易度別の勝率レンジと、上記の「有利／不利になる条件」の両立を `npm run playtest` で検証し、回帰を検知する。

### RI-73 Nightmare は AI 依存を意識しない方針で第1スプリント敗北が確定する

nightmare は26方針260ランすべて敗北し、うち215ランが `aiDependency`。敗北までのスプリント数 p50 は 1 で、他の敗因（2〜24）と比べて突出して短い。回避経路は2種類ある。依存度を下げる経路（`onlyThrottle` / `noAi`）と、**リテラシーを上げて敗北条件そのものを外す経路**（`onlyPair` は依存度100のまま最終リテラシー 62 で `aiDependency` 敗北 0/10）である。とくに `pairReview`（「詰まったPRをペアで処理。AI Literacy が上がる」）による回避は SPEC 第19章の主題に最も合致する。それ以外の方針は最終リテラシー 25.0・依存度 100 で 10/10 が第1スプリント敗北する。回避経路はいずれも勝率 0/10。敗北条件は `org.aiDependency >= 95 && org.aiLiteracy <= 30`（`src/sim/outcome.ts:63-65`）で、nightmare の初期値 `aiDependencyBase`=55 / `aiLiteracy`=25（`src/data/difficulties.ts`）はリテラシー側を最初から満たしている。`aiDependency` は AI 割当タスク1件ごとに `AI_DEP_PER_TASK`=2.2 加算され（`src/sim/sprint.ts:193`）、`taskCountMul`=1.2 のタスク量で第1スプリント中に 95 へ到達する。問題は回避不能なことではなく、**回避に必要な方針が事前知識を要し、外すと第1スプリントで終わる**こと。SPEC 第19.1 F-8（詰みの確定を作らない）違反であり、初手で終わるため「負けて学ぶ」も成立しない。

依存度を下げる手段は既に存在する（カード `ai-guideline` の `aiDependencyAdd: -10`、レバー `aiGuideline` / `teamAiThrottle` の `aiDependencyDelta: -10`、`aiThrottleDept` の -8）。一方で AI を抑えない方針の最終依存度は全難易度で上限に張り付く。カードはドラフトの引き次第、レバーは四半期予算を消費するため、既定方針では低下手段が実質機能しない。リテラシー経路（ペアレビュー）も、チュートリアルにもリザルトにも現れず発見の手掛かりが無い。したがって不足しているのは手段の有無ではなく、既存手段の効果量・入手機会・発見性である。

受入条件:

- Nightmare で、事前知識のない方針が第1スプリントで敗北しない。
- AI 依存敗北の回避経路（依存度を下げる／リテラシーを上げる）がプレイ中に発見できる。とくに `pairReview` によるリテラシー上昇が敗北条件を外すことを、チュートリアルまたは敗北時の提示で伝える。
- 既存の依存度低下手段（`ai-guideline` カード・AI 系レバー）の効果量・入手機会・発見性を、1スプリントあたりの上昇量と釣り合う水準へ見直す。新規手段の追加はこの見直しで足りない場合に限る。
- 通常プレイで `aiDependency` が上限に張り付かず、意思決定の入力として機能する。
- AI 依存敗北が、盤面・HUD で数スプリント前から予兆として見える。
- 難易度別の `aiDependency` 推移と敗北到達スプリントをユニットテストで検証する。

### RI-74 スプリントが規定の半分の長さで、難易度が低いほど短い

1x 換算（`MS_PER_TICK_1X`=680ms）の通常スプリント長 p50 は easy 27.2秒 / normal 36.0秒 / hard 46.2秒 / nightmare 104.7秒。SPEC 第3.1 の規定「通常60〜120秒・最短でも30秒」に対し、easy は**55.2%が絶対下限の30秒を割り**、95.7%が60秒未満。p10 は11.6秒で、盤面を見る前に終わるスプリントが常態化している。ボススプリント（規定90〜180秒）の p50 は easy 36.0秒 / normal 44.2秒 / hard 52.4秒 / nightmare 86.4秒で、全難易度が規定下限を下回る。初見が最初に触れる easy が最も短く、F-4 の「ゆっくり流れる時間 + 締め切り」と逆になっている。既存のペーシング回帰テスト（`tests/unit/sprintTempo.test.ts`）は、無介入経路（`collectSprintTicks` はカードも介入も発動せず `step` だけで進める）で通常スプリントの絶対下限・p50・p90 を既に検査しているが、**normal 難易度のみ**を対象とするため easy / hard / nightmare の崩れを検知できない。ボスについても上限（180秒）しか検査しておらず、下限（90秒）は未検査。後段の RI-66 統計は `skilled` 相当のポリシーで別途測っている。

受入条件:

- 全難易度で通常スプリントの p50 が第3.1 の 60〜120秒帯に入り、30秒未満が生じない。
- ボススプリントの p50 が 90〜180秒帯に入る。
- ペーシング統計検証（RI-66）を全難易度・無介入方針を含む条件へ拡張する。

### RI-75 勝利種別が実質2種で、最も受動的なプレイが最上位勝利を取る

840ラン中279勝の内訳は `healthy` 153（55%）/ `noDamage` 125（45%）/ `happiness` 1 で、`aiSuccess` / `management` / `chaos` / `normal` は0件。`evaluateWinType`（`src/sim/outcome.ts:103-118`）が固定の優先順ラダーで、先頭の判定が `!usedHeavyActions && totals.spread === 0` のため、残業もアンドンも使わない受動的なプレイほど「やり込み枠」であるはずのノーダメージ勝利になる。実測でも勝利種別は「重アクションを使ったか」だけで分岐している。組織診断も同様に偏る（`seniorSacrifice` 453 / `reviewHell` 342 / `documentationKingdom` 19 / `healthyAcceleration` 15 / `aiOverproduction` 10 / `reworkSpiral` 1）。SPEC 第19.1 F-10 が求める「ビルドによって目指す勝ち筋が変わる」が成立していない。

受入条件:

- プレイヤーが目指す勝ち筋を選択・宣言でき、その選択が四半期目標や評価に反映される。
- ノーダメージ勝利が、受動的なプレイでは到達しない難度になる。
- 代表 seed × 複数ビルドで、勝利種別が2種以上に有意に分かれることを検証する。

### RI-76 AI 導入が既定 ON で「AI を入れるか」の意思決定が存在しない

初期ロスターは `aiAssigned: arch.preferred === 'coding'`（`src/sim/member/roster.ts:135`）でコーダーに最初から AI が配られており、既定プレイの AI 利用率は 82.5%、最終 AI 依存度は 100。明示的な「AI 全配布」方針（`aiFullBet`）は既定とほぼ同じ結果になる。一方 AI 配布を全解除すると別のゲームになる（easy スプリント平均で 出荷 334.5→291.4、AI 利用率 82.6%→0%、最終 AI 依存度 100→33.4）。因果自体は正しく効いている。

選択の入口は存在する。新規ランは第1スプリント前に必ず `SetupScreen`（見出し「編成 — スプリント開始前に配置とAIを決める」）を通り、`FormationScreen.tsx:172` の「🤖 AI配布中」ボタンから `setMemberAi` で解除できる。したがって課題は場の不在ではなく次の3点である。(1) 既定が ON で、既定のまま進むのが有利なため、選び直す動機が無い。(2) 解除側の代償が一方的に大きい。`noAi` は全難易度合計 9/40 で、`budgetExhausted` 敗北25件のうち14件を占める。AI で稼げないぶん予算を維持できず、AI 導入が実質必須になっている。(3) 導入が編成画面の on/off だけで段階が無く、「どこまで広げるか」を四半期を通じて問い直す機会が無い。

受入条件:

- 開始時の既定値が、そのまま進めるだけで有利な状態でなくなる（既定のまま／解除の双方に成立条件がある）。
- AI を入れない選択が、目標未達による敗北へ一直線に繋がらない（別の勝ち筋が成立する）。
- AI の導入度合い（誰に配るか・どこまで広げるか）が、ラン中に複数回問い直される段階的な意思決定になる。
- 開始時 AI の全面撤廃は取らない。`SetupScreen` / `FormationScreen` の既存の編成上の意思決定を重複して作り直さない。
- AI あり／なしの結果差が代表 seed で検証されている（`tests/unit/helpers/aiAdoptionSeeds.ts` の枠組みを利用する）。

### RI-77 カードが集中力だけを消費し、勝率を動かさない

当初「介入すべき状況が盤面に現れない」としていたが、これは誤りだった。毎 tick 全8種の介入を試す `probe` 方針で発動可能回数の上限を測ると、成立回数は easy p50=7 / hard p50=8 / nightmare p50=8 で、いずれも SPEC 第3.1 の「1スプリントあたり 3〜8回」の帯に収まる。介入の機会自体は足りている。

実プレイ相当の方針が p50=1〜3 に留まる原因は集中力の奪い合いである。カードだけを外す統制条件（`skilledNoHire` → `skilledNoCards`。採用条件は両方 `skip` で揃えてある）では、集中力不足による介入失敗（`no-focus`）が完全に消え、介入成立数が 1.1〜2.2 倍になる（easy ok=213 / no-focus=258 → ok=350 / no-focus=0。normal 269/718 → 582/0。hard 446/2006 → 476/0）。にもかかわらず勝率は変わらない（easy 8/10→9/10、normal 5/10→5/10、hard 3/10→2/10。全40ランでは 16 と 16）。つまりカードは共通資源である集中力を大量に消費しながら、結果に寄与していない。SPEC 第19.1 F-2 が求める「スプリント間の投資が結果を変える」が第2層で成立していない。

対象不足（`no-target`）はアクションによって大きく異なる（単一介入方針で測った、試行のうち `no-target` で失敗した割合）。`firefight` は easy 89.5% / normal 86.9% / hard 82.2%、`assignTask` は easy 78.9% / normal 90.2% / hard 94.9% / nightmare 98.2%、`interruptReview` は 41.7〜57.5%、`splitPr` は 45.8〜60.7%。一方 `overtime` / `andon` / `pairReview` / `aiThrottle` は対象を要さず 0%。とくに `assignTask` は難易度が上がるほど空振りし、`firefight` も easy で約9割が空振りする。

受入条件:

- カードの発動が勝率・組織状態に有意な差を生む（統制条件との比較で確認できる）。
- カードと介入が集中力を共有する構造を残す場合、どちらを取るかの正解が難易度で固定されない。
  共有をやめる場合は、カード専用のコスト資源を導入して介入の集中力予算と切り離す。
- 対象を要する4種（`firefight` / `assignTask` / `interruptReview` / `splitPr`）について、対象の発生頻度と撃ちたくなる頻度が釣り合う。とくに `assignTask` が高難易度でほぼ空振りする状態を解消する。
- 上記を `npm run playtest` の統制方針（`skilledNoCards` 等）で検証し、回帰を検知する。

### RI-78 予算枯渇・信頼枯渇が予兆なく終わり、敗因ラベルが実態と一致しない

敗因ごとの進行速度は明確に異なり（敗北までのスプリント数 p50 が `aiDependency` 1 / `seniorBurnout` 2 / `moraleCollapse` 2 / `techDebt` 3 / `reviewFreeze` 7 / `budgetExhausted` 11 / `reorgRequired` 18 / `trustExhausted` 24）、この点は F-9 として良い。問題は予兆とラベルの2点である。

第一に、`budgetExhausted` / `trustExhausted` / `reorgRequired` は直前スプリントのシニアHP 54〜63・士気 98〜100 のまま終わる。盤面上は健全に見えるのに終了するため、F-6（次の一手が分かる）と F-8（詰みの確定を作らない）を満たさない。

第二に、**`trustExhausted` ラベルが3種類の原因を1つに潰している**。`loseReasonForOutcome`（`src/sim/run/quarterReview.ts:464`）は `missed_crisis` と `shutdown` の**両方**を `trustExhausted` に変換する。840ランでの発火条件の内訳は、`missed_crisis` が `trust<=15` のみ18件 / `budget<=5` のみ8件 / `missedCount>=4` のみ0件、`shutdown` が `seniorHp<=5 かつ missedCount>=2` 2件。つまり `trustExhausted` 28件のうち信頼由来は18件で、**残り10件は予算切れ（8件）とシニア枯渇（2件）**である。予算やシニアが原因のランに信頼回復を促しても解決しない。

受入条件:

- 予算・信頼が危険域に入ったことが、数スプリント前から HUD で警告される。
- 危険域に入った後に、予算・信頼を回復・延命する打ち手が存在する。
- `missed_crisis` と `shutdown` の発火条件（信頼 / 予算 / KPI未達件数 / シニア枯渇）が敗因ラベルと表示に反映され、
  プレイヤーが実際の原因を特定できる。
- 敗因別に、直前スプリントの盤面指標が危険域に入っていることを `npm run playtest` で検証する。

### RI-79 スプリント評価が S に偏る

840ラン・6,322スプリントの評価分布は S 3855（61.0%）/ A 1347（21.3%）/ B 514（8.1%）/ D 333（5.3%）/ C 273（4.3%）で、S と A が82%を占める。無介入の `passive` だけを見ても S が約半数（152/315＝48%）で、評価がプレイの巧拙を反映せず、フィードバックとして機能していない。

受入条件:

- 無介入方針の評価中央値が、熟練方針より明確に低い。
- 評価分布が特定ランクへ半数以上偏らない。

### RI-80 ドラフトのマリガンが無い

`DraftScreen` の選択肢は「3枚から1枚選ぶ」か「スキップ」のみで、コストを払って引き直す手段が無い。カードプールも9枚（`src/data/cards.ts`）で、うち4枚はメタ解放が必要なため初期プールは実質5枚。SPEC 第19.1 F-12 が求める「事故で負けた」→「コストを払ってでも引き直すか」への変換が成立していない。RI-77 のとおりカードは現状ほぼ結果に寄与していないため、マリガン導入はカード自体の効果量見直し（RI-77）とセットで扱う。

受入条件:

- ドラフトでコスト（予算・集中力・信頼など）を払って引き直せる。
- 引き直しコストが、引き直すかどうかを迷う水準に設定されている。
- カードプールが、ドラフト3枚の組み合わせに意味が出る規模まで拡張されている。

### RI-81 敗北画面に「次の一手」が無い

`RunResultScreen` が敗北時に示すのは敗因ラベル＋一文の説明（`LOSE_LABEL`、`src/ui/RunResultScreen.tsx:26-52`）、組織タイプ診断、メタ進行ポイントで、次のランで何を変えるかは提示されない。教訓文（`FAILURE_LESSONS`、`src/sim/diagnosis.ts:64-81`）は初回敗北でも表示される（`recordIfFinished` が `applyRunReward` 経由で失敗診断を `collectedDiagnoses` へ加えてから画面を更新するため、`failureInCollection` は初回時点で true）。問題は対応範囲と粒度で、教訓は敗因（`LoseReason` 10種）ではなく組織タイプ診断に紐づき、しかも `FAILURE_LESSONS` が対応するのは失敗診断4種のみ。診断が `healthyAcceleration` / `documentationKingdom` のまま敗北すると `failureEntry` が存在せず教訓が一切出ない。また `budgetExhausted` / `trustExhausted` / `aiDependency` / `reorgRequired` で負けても表示は診断由来の一般論で、その敗因に対する次の一手にならない。SPEC 第19.1 F-6 は「初見は負けて学ぶ」の前提条件であり、学びが敗因に噛み合っていない。

受入条件:

- 敗因（`LoseReason`）に対応した「次のランで変える具体的な一手」が表示される。
- 診断が失敗4種以外でも、敗北時に必ず教訓が表示される。
- 教訓が現実の開発現場への示唆としても読める文言になっている（SPEC 第20章）。

### RI-82 目標修正の選択が結果を変えない

目標修正だけを固定する統制方針（`adjCutScope` / `adjExtendDeadline` / `adjQualityPivot`、各40ラン。うち実際に該当の修正が提示され選べたのは各15ラン。修正を選んだ四半期は3条件とも平均1.3で揃っており事前状態は比較可能）の結果は、勝率 60.0% / 60.0% / 73.3%、最終到達四半期 平均 2.7 / 2.8 / 2.3、総スプリント 平均 14.5 / 15.6 / 12.9。**`cut_scope` と `extend_deadline` は完全に同じ勝率**で、`quality_pivot` がやや高いものの n=15 では有意と言い切れない。目標修正フェーズ自体は840ラン中315ラン（37.5%）で発生しており選択機会は十分にあるが、選択が後続を明確に分岐させていない。SPEC 第19.1 F-2 が求める「四半期レビューの目標修正でジレンマが成立する」を満たさない。

なお当初の集計では `quality_pivot` の勝率を 83.3% としていたが、これは統制していない方針のランが提示順の先頭である `cut_scope` 群へ大量に混入した結果のアーティファクトだった。また「到達四半期」に終端の `quarterNumber` を使っていたため、修正を選んだ時期ではなく後続のラン長を見ていた。いずれも訂正した。

受入条件:

- 目標修正の選択肢ごとに、後続四半期の進み方（勝率・到達四半期・組織状態）が有意に分かれる。
- 各選択肢に、それが有利になる局面と不利になる局面がそれぞれ特定できる（F-1）。
- 選んだ代償が次四半期以降に現れることが、プレイヤーに追跡できる形で提示される。
- 統制方針での比較を `npm run playtest` で検証し、回帰を検知する。

### RI-83 条件を揃えると介入の寄与がほぼ消える

`noInterventionCtl`（`skilledNoHire` から介入だけを外し、カード・進化・採用を揃えた統制条件）との比較で、勝率は easy 7/10・normal **6/10**・hard 0/10（全40ランで13）。対する `naive` は 6/5/2（13）、`skilledNoHire` は 8/5/3（16）。**normal では介入しない方が勝っており**、全40ランでも介入の寄与は最大 +3 に留まる。分散も同様で、同一スプリント番号の出荷 CV は easy S2 で `noInterventionCtl` 20.3% / `skilledNoHire` 20.8%、S3 で 29.8% / 30.8% とほぼ同じ。

当初「介入は勝率を改善している（完全放置 7 → 熟練 16）」としていたのは、進化・カード・採用が同時に変わっていたためだった。介入だけを統制すると期待値でも分散でも寄与がほとんど無い。SPEC 第19.1 F-5 は「無介入は損ではなく不安定。介入の価値は結果の偏差を抑えること」と定義しているが、実装は期待値も分散も動かしていない。

受入条件:

- F-5 の定義と実装のどちらを動かすかを決め、SPEC 第19.1 に反映する。
- 実装側を動かす場合、`noInterventionCtl` と介入方針の間に、勝率または同一スプリント番号の出荷 CV で有意な差が出る。
- 介入しない方が勝つ難易度が無い。
- 判定を `npm run playtest` の統制方針で検証し、回帰を検知する。

### RI-84 敗北の大半がスプリント間フェーズで確定する

敗北を検知したフェーズを記録すると、主要2敗因のほぼ全件が**スプリントを走り切った後のビート（スプリント間イベント）で確定**していた。easy の `seniorBurnout` 27件・`reviewFreeze` 22件は全件が `beat`、normal も `seniorBurnout` 62件中61件・`reviewFreeze` 54件全件が `beat`、hard も `seniorBurnout` 88件中81件・`reviewFreeze` 74件中73件が `beat`。この2敗因は敗因全体の55%（1,040ラン中354件）を占める。

プレイヤー体験としては、リアルタイムで盤面を捌き切った直後に、操作の余地がない画面で敗北を告げられることになる。SPEC 第19.1 F-4 が想定する「リアルタイム層で勝負が決まる」構造にも、F-8 の「詰みの確定を作らない」にも反する。なお `techDebt`（hard で `sprint` 9 / `beat` 2）と `moraleCollapse`（hard で `sprint` 8 全件）はスプリント中に決まる割合が高く、敗因ごとに手触りが違う点自体は F-9 として良い。問題は主要2敗因の決着位置が偏っていることである。

受入条件:

- `seniorBurnout` と `reviewFreeze` の敗北が、スプリント中に決着する割合を高める。
- スプリント間フェーズで敗北が確定する場合、その直前のスプリント中に警告と対処の機会がある。
- 敗因ごとの決着フェーズ分布を `npm run playtest` で検証し、回帰を検知する。
